# HappyLocale ロードマップ

最終更新: 2026-09-03

このロードマップは、HappyLocaleをローカル実行のカード・ルールブック翻訳支援ツールとして段階的に改善するための優先順位を示します。日々の実装状況や技術的な引き継ぎは `DEVELOPMENT.md`、状態管理の設計は `DESIGN.md`、利用方法は `README.md` を参照してください。

進捗はチェックボックスで管理します。

- `[x]`: 実装と基本検証が完了
- `[ ]`: 未実装、または完了条件を満たしていない

## 基本方針

- 元画像、切り出したアセット、フォント、編集結果を運営側サーバーへ送信しない
- 利用者が選択した素材をローカルで編集し、素材の利用条件はREADMEで注意喚起する
- 画像検索、画像収集、翻訳済み画像の共有基盤は作らない
- Canvas中心の軽量な構成を維持し、重い依存関係は効果を検証してから導入する
- 自動処理だけで完全な結果を目指さず、人が修正できる操作を先に整える
- 新機能よりも、保存データの互換性と既存編集操作の安定性を優先する

## 現在地: MVP

現在、次の一連の操作が成立しています。

- [x] PNG / JPEGをローカルで開く
- [x] 翻訳領域を作成・移動・リサイズする
- [x] 自動補修、手動マスク、単色塗りつぶしで元テキストを除去する
- [x] 元画像を変更せず、領域へ文字とインラインアセットだけを配置する
- [x] 日本語訳、縁取り文字、カスタムフォント、インラインアセットを描画する
- [x] CSVで翻訳を入出力する
- [x] PNG / JPEGを書き出す
- [x] Chromeのローカルフォルダへプロジェクトを保存・再読込する

背景補修、保護領域、アセット編集などは利用可能ですが、複雑な画像での品質と操作性には改善余地があります。

## 最終的な理想ワークフロー

1. 複数のカード画像をローカルフォルダから一括登録する
2. 一覧では軽量なサムネイルだけを表示し、原寸画像はカード編集を開いたときに遅延読込する
3. 各カードのテキスト領域候補を自動検出し、利用者の確認後に領域として作成する
4. 作成した領域へOCR結果を元テキストとして入力し、補正候補を確認できるようにする
5. 元テキストの翻訳結果を各領域の訳文へ反映する
6. カードごとに、印刷へ含める範囲を手動指定する
7. 最初のカードで指定した印刷範囲を他カードの初期値として利用し、カードごとに微調整する
8. 複数カードの印刷範囲を、はみ出しを確認しながら同一縮尺でA4へ面付けして出力する

画像、OCR、アセット、フォントは引き続きブラウザと利用者が選択したローカルフォルダ内だけで扱います。自動処理は一括確定せず、カード一覧から処理状態と結果を確認・修正できる設計にします。

### 実装方針

最初はCanvas上の色差による背景除去と手動補正を組み合わせます。複雑な輪郭に対して自動処理だけで完全な透過を狙わず、プレビューとブラシ修正を必須の逃げ道にします。

初版では、切り出し画像の外周から多数派の背景色を推定し、外周につながっている近似色だけを透過します。これにより、アイコン内部に閉じ込められた同系色を可能な範囲で保持します。背景色はカラーピッカーまたはプレビュー上の画素から手動指定もできます。許容色差、境界ぼかし、追加・消去ブラシは作成中だけ調整し、確定後は補正済みの透過PNGとして保存します。元画像を再選択すれば、アセットIDと表示設定を維持したまま切り出し範囲と透過結果を更新できます。

## 並行トラック: PDF文字翻訳

PDF文字翻訳は、画像カード編集とは状態と保存形式を分離した専用画面で進めます。現在のMVPでは、文字PDF・画像PDF・混在PDFの判定、文字PDF専用CSVの往復、ページプレビュー、CSV対象行の個別除外・原文修正・読み順変更・結合・分割、画像ページの選択範囲OCR、保護領域、局所背景補修、回転・CropBox・MediaBox座標変換、TTF / OTFを埋め込んだ検索・選択可能な訳文配置、ページ単位の進捗表示とキャンセル、パスワードPDFの明示的拒否、フォーム・リンク・注釈の検出警告、PDF専用サイドカーJSONへの状態保存と元PDFのSHA-256照合を実装済みです（2026-09-03）。ページ数にはハード制限を設けず、ページ単位で処理・解放します。ファイル容量は100 MiBを上限とします。

詳細な実装状況と制約は[`PDF_TRANSLATION_ROADMAP.md`](PDF_TRANSLATION_ROADMAP.md)で管理します。

- 運営側サーバーへの画像・プロジェクト保存

- 翻訳済みカード画像の共有・公開機能
- フォントファイルの同梱、配布、プロジェクトへの埋め込み
- 利用者の確認なしに画像を外部AIへ送信する機能
- アカウント、課金、チーム共有を前提としたSaaS機能

## 優先順位の決め方

新しい要望は、次の順で評価します。

1. データ損失や既存プロジェクトの互換性に関わる問題
2. 編集結果が意図と異なる不具合
3. 日常操作を妨げるUI上の問題
4. 背景補修とアセット品質の改善
5. 複数カードでの作業効率
6. 外部サービス連携
7. 高度だが利用頻度が未確認の機能

小さな変更は単独で実装・検証し、複数の独立した作業へ安全に分割できる大規模変更だけ、必要に応じて並行作業を検討します。

## 更新ルール

- 完了した項目は `[x]` に変更して削除せず、分かる範囲で完了日と関連コミットを追記する
- 一部だけ完了した項目は、完了部分と残作業を別のチェックボックスへ分割する
- 優先順位を変更した場合は理由を短く記録する
- 新しい依存関係を前提にする項目は、導入条件と代替案を併記する
- `DEVELOPMENT.md`の既知の課題と矛盾しないよう同じ変更内で確認する
- 固定日程ではなく、各Phaseの完了条件を満たした時点で次へ進む
