# HappyLocale アーキテクチャ

最終更新: 2026-09-20

この文書は現在の実装を説明します。Pinia移行時の設計背景は[アーカイブの設計記録](archive/DESIGN.md)、今後の機能計画は[ロードマップ](ROADMAP.md)を参照してください。

## 設計上の前提

HappyLocaleは、カード画像やルールPDFを手元で編集するlocal-firstのWebアプリです。運営側の画像保存サーバーを設けず、画像、PDF、プロジェクトデータ、フォントをブラウザとユーザー指定フォルダ内で扱います。素材の利用条件に関する注意事項は`README.md`に記載しています。

この方針には次の目的があります。

- 素材を第三者の保存基盤へ集約しない
- サーバーの保管期間、容量、認証、削除要求を設計対象に増やさない
- オフラインに近い環境でも編集できる
- 元データの保存場所を利用者自身が管理できる

例外はローカル起動版のα機能であるTranslation Endpointです。有効にした場合、原文テキストと入出力言語をユーザー指定のHTTP(S) Endpointへ送信します。画像、PDF、フォント、APIキーは送信しません。外部URLを指定した場合は、その外部サービスがデータの送信先になります。静的公開版（`pnpm build:static`で生成）ではこの機能をビルド時に無効化します。

## 全体構成

```text
pages
  ├─ /        → 作業選択ホーム
  ├─ /cards   → CardEditor
  └─ /pdf     → 公開停止中の案内ページ（PDF編集実装は app/features/pdf/ に保持）

AppNavigation
  └─ ホーム、カード編集、PDF翻訳の共通移動

CardEditor
  ├─ projectStore             project.json互換の正規データ
  ├─ useCardEditor            カード単位の編集状態と操作
  ├─ useHistory               JSON互換スナップショット履歴
  ├─ useProjectRuntime        画像・フォント・フォルダ等の寿命管理
  ├─ 操作別composable         保存・読込・カード操作・OCR・翻訳
  └─ features/cards
       ├─ useCardWorkspace    画面状態と領域操作
       ├─ useProjectActivity  保存・読込・追加・切替の排他判定
       └─ CardEditingWorkspace → Canvas・Inspector・確認ダイアログ

操作別composableと描画UI
  ├─ services/project         project.jsonとフォルダI/O
  ├─ services/ocr             OCR Providerと前処理
  ├─ services/translator      翻訳Provider
  ├─ services/fonts           FontFaceとIndexedDB
  └─ utils/canvas             背景・文字・アセット描画
```

カード編集とPDF翻訳は状態・保存形式・画面を分離し、作業選択ホームから移動します。ホームでは共通ナビゲーションを表示し、編集画面では縦の作業領域を確保するため、各ツールバー左端の`WorkspaceSwitcher`へホーム・カード・PDF間の移動を集約します。カード編集のツールバーは作業切替、編集モード、保存、履歴を主要操作とし、低頻度のプロジェクト変更、CSV、用語集、翻訳設定をツールメニューへ集約します。右パネルは一覧・領域・OCR・翻訳・印刷範囲の排他的な5タブです。A4面付けは右パネルへ押し込まず、カード一覧からメイン作業領域へ開きます。`CardEditor.vue`は、Store・編集・ランタイムと操作別composableを生成して接続する調整役です。保存は`useProjectPersistence`、読込は`useProjectSession`、カード操作は`useProjectCards`、切替は`useProjectNavigation`へ分離しています。OCR・翻訳・アセット・フォント・画像出力も操作別composableが担当します。

PDF編集はversion付きの専用サイドカーJSONへ解析結果、翻訳、除外ID、保護領域、描画設定を保存します。version 2でページ回転角とviewport変換行列を追加し、version 1は無回転の変換行列を補って移行します。元PDFのバイト列は保存せず、解析時に計算したSHA-256指紋を保持します。復元時に利用者が再選択した元PDFの指紋が一致した場合だけ状態を読み込みます。

## 機能内の配置と接続

カード編集専用の接続は`app/features/cards/`へ配置しています。`useCardWorkspace`は表示倍率・プレビューモード・Inspectorタブ・領域操作をまとめ、`CardEditingWorkspace`がCanvas・Inspector・領域の確認ダイアログを接続します。印刷・アセット画面への切替ではWorkspaceを破棄せず、選択と表示倍率を保持します。

`cardEditingContext.ts`は編集・描画資源・OCR・翻訳の用途別に型付きのprovide/injectを定義します。`cardEditingContracts.ts`で子画面が使うAPIを列挙し、実装の戻り値へ操作を追加しても自動的に公開型が広がらないようにしています。親で作った同じインスタンスを共有し、保存・資源解放などのAPIは子の型へ公開しません（別インスタンスの生成や実行時のアクセス制御ではありません）。原文アイコン確認の`useSourceIcons`はWorkspaceで生成し、Inspectorには確認を開く操作だけを共有します。

`useCandidateReview`は候補の作業コピーの復元・退避・確定・破棄を担当します。保存側の候補変更を同期監視し、通常Undoや混在適用で変わった値を表示へ戻して古い候補編集履歴を破棄します。自分のドラッグ・分割等の保存通知では履歴を維持し、他カードの編集・通常領域だけの変更・JSON項目順の違いでは初期化しません。カード切替や候補削除では無効なフォーカスを外しますが、外部同期だけでプレビューモード・Inspectorタブ・通常領域の選択は切り替えません。候補検出・編集履歴の所有は`useRegionCandidates`、カード別候補の保存と次カードへのレビュー進行は既存のStore・一括OCR側に残します。Canvasは背景色を取得する関数だけを渡し、レビュー操作はWorker・Canvas資源・フォルダI/Oを所有しません。

診断は`useEditorDiagnostics`が画面ごとに直近50件を保持し、表示用の型は`types/diagnostics.ts`で共有します。`useEditorNotifications`は既存の通知期限を維持し、スコープ終了時にタイマーを全解除します。`useEditorHistoryShortcuts`はマウント中だけキーイベントを購読し、処理中・別画面・入力欄・モーダルの履歴操作を横取りしません。これらの状態は保存文書へ含めません。

画像の反映は`useEditorImageAdoption`、読込済み文書の採用は`useProjectAdoption`が担当します。前者は最初の下書き画像・アセット切り出し元・カード画像の反映とDPI読取を接続し、後者は新規フォルダ／既存文書の異なる初期化順を保ってStore・履歴・runtimeへ反映します。画像の検証・デコードと未採用画像の解放は`useEditorImageLoading`、プロジェクトのI/O・準備中断・未採用アセットの解放は`useProjectSession`、採用後のブラウザ資源の所有は`useProjectRuntime`に残します。カード切替では既存の`useProjectNavigation`がカード別履歴を維持します。

採用側も待機後に対象を照合します。DPIは同じフォルダ・カードオブジェクトで未設定の場合のみ反映し、手動設定を上書きしません。下書き画像・アセット元画像は最新の要求だけを採用し、不要になった未採用URLは解放します。サムネイルは要求世代・フォルダ・呼出元の有効性を確認してから登録し、失敗しても採用済みのカード画像は解放しません。新規フォルダ／プロジェクト採用後の`nextTick`による保存署名更新も、画面終了や別の採用後は無効です。

PDF専用UIとcomposable、その単体テストは`app/features/pdf/`へまとめています。複数機能が使う部品・サービス・型は共通配置に残し、親画面との接続テストとE2Eは`tests/`へ置きます。既存のカード操作別composableは`app/composables/`にあり、すべての機能をコロケーション済みという意味ではありません。

## 状態の境界

### 永続プロジェクトデータ

`FolderProjectDocument`は`project.json`へ保存できるJSON互換データです。

検証済みの文書とアセット・フォント参照、OCR辞書、用語集はPiniaの`projectStore`が所有します。表示中カードの編集・Undo・Redo結果は`useCardEditor`からカードID付きでStore actionへ即時同期し、保存とカード切り替えではStoreの正規データを使用します。

- プロジェクト名と形式バージョン
- カードID、表示名、画像の相対パスと寸法
- 翻訳領域、保護領域、手動マスク座標
- 原文、訳文、翻訳ステータス、横・縦位置を含む描画設定
- 共有アセットとフォントの参照情報
- OCRユーザー辞書
- 翻訳用語集（原文、訳語、メモ）
- カードごとの印刷範囲と元画像DPI、A4面付け設定

画像、Blob、Object URL、`HTMLImageElement`、`ImageBitmap`、`FontFace`、`FileSystemDirectoryHandle`は含めません。カード一覧用JPEGは`thumbnails/<card-id>.jpg`へ派生キャッシュとして保存し、`project.json`から参照しません。

### 編集セッション

選択中のカード・領域、表示倍率、現在のツール、プレビュー状態、削除予定ID、未保存アセットBlobなどは実行中だけ保持します。削除予定カードは保存が成功するまで永続配列と画像ファイルを残します。

`useCardWorkspace`は画面内の状態を管理し、Piniaの`editor-tools` StoreはCanvasとInspectorで共有する編集モード・ブラシ設定だけを保持します。このStoreは永続化せず、Workspaceの所有スコープ終了時にリセットします。

保存・読込・追加・切替の実行状態は各composableが所有し、`useProjectActivity`が登録された参照から`busy`を導出します。一括画像出力の状態は`useCardImageExport`が別途所有します。OCRも共通の実行状態を単一領域・候補検出・一括処理で共有し、二重実行を防ぎます。

### ランタイムリソース

カード編集のブラウザ固有リソースは`useProjectRuntime`が所有し、永続プロジェクト状態やUI状態から分離します。

- 表示中カード: `HTMLImageElement`とObject URL
- カードサムネイル: 表示範囲付近だけ読み込むBlobとObject URL
- アセット: `ImageBitmap`またはCanvas
- 未保存アセット: Blob
- フォント: 読み込み済みの`FontFace`
- プロジェクトフォルダ: `FileSystemDirectoryHandle`

フォントBlobのIndexedDBへの保存・復元は`useEditorFonts`と`app/services/fonts/`が担当します。

カード一覧は`IntersectionObserver`で表示範囲の前後300pxを監視し、サムネイルを最大2件並列で読み込みます。キャッシュがなければ元画像を縮小して保存し、破損または規定寸法を超えるキャッシュも再生成します。Object URLは置換・プロジェクト変更・画面破棄時にrevokeし、`ImageBitmap`は不要になった時点でcloseします。登録した`FontFace`は削除時や画面破棄時に`document.fonts`から外します。

サムネイルキャッシュのFileは再書込で読めなくなるため、読込時にバイト列をBlobへ複製してから検証・表示します。遅いキャッシュ読込は既に生成した新しい画像を上書きしません。元カード画像全体の複製を増やす変更ではありません。

カード用OCR Providerは`CardEditor`が生成・破棄し、単一領域・候補検出・一括OCRで同じWorkerを再利用します。Workerは`useProjectRuntime`の管理対象ではありません。

TesseractのWorkerは同一アプリの配信ファイルを直接起動し、ライブラリ側のBlob URLラッパーを作りません。WASM・学習データと合わせてNuxtのbaseURLを付け、CDNへフォールバックしません。

## Canvas描画

`app/features/cards/canvas/geometry.ts`は表示座標から原画像座標への変換、ヒット判定、矩形の移動・リサイズを担当する純粋関数です。通常領域・OCR候補・保護領域・印刷範囲が同じ計算を使い、候補だけ辺中央のハンドルも判定します。ドラッグ中は小数を保ち、確定時に整数化します。DOM・Store・描画資源は所有しません。

同じディレクトリの`renderer.ts`は元画像・編集済みプレビューのCanvasキャッシュを所有し、`CardCanvas`のスコープ終了時に参照を破棄します。画像・アセット・フォントは借用し、解放責任を移しません。`overlays.ts`は選択枠・候補・保護領域・マスク・印刷範囲の編集用表示だけを描画します。プレビューとPNG/JPEG出力は既存の`renderCard`を共用し、出力経路へ仮ドラッグ・選択枠を渡しません。

倍率やアセット画像Mapの差し替えも再描画の対象です。同じtickの変更はpost-flush watchで集約し、倍率・選択だけの変更では本体キャッシュを再利用します。文書・画像・アセット・フォント参照の変更でキャッシュを失効させ、入力中の描画保留は解除まで維持します。

`useCanvasInteractions`はポインター操作の優先順と仮状態を所有します。入力・編集ツール・確定コールバックを受け、描画用の仮状態とイベントハンドラーを公開します。Storeや履歴を直接更新せず、`CardCanvas`が従来のprops/eventsへ接続します。

ドラッグは1ポインターだけが所有し、開始時の画像・編集文書・選択・候補集合・ツール・倍率を照合します。変更検知とイベント受信時に対象を再確認し、pointercancel・画面スコープ終了では未確定状態を破棄して捕捉を解除します。途中のlostpointercaptureでは矩形操作を破棄し、ブラシだけは対象が有効なら既存どおり1筆を確定します。通常release後の印刷2クリック選択は維持し、捕捉解除による二重確定を防ぎます。

描画処理はUIから分離した関数へ寄せています。

- `app/utils/canvas/background.ts`: 背景色推定、文字マスク、簡易補間、手動マスク
- `app/utils/canvas/text.ts`: 日本語を含む折り返し、領域へ収めるフォント縮小
- `app/utils/canvas/inline.ts`: 文字とインラインアセットの解析・配置
- `app/utils/canvas/asset.ts`: アセット切り出しと背景透明化
- `app/utils/canvas/render.ts`: カード全体の描画手順

背景補修はTypeScriptとCanvasで実装しています。OpenCV.jsやAI補修を先に導入せず、依存サイズを抑え、ブラウザ内で完結し、人がマスクを修正できることを優先した選択です。複雑な模様を完全に再構成することは対象外です。

編集プレビューとPNG／JPEG出力は同じ描画経路を使い、表示倍率だけを出力へ持ち込まない設計です。

A4面付けは編集済みカードを原寸Canvasへ描画して印刷範囲を切り出し、PNGまたはJPEGのDPIメタデータからピクセル寸法をミリメートルへ換算します。メタデータがない画像は推測せず、利用者がDPIを指定するまでPDF出力を止めます。既定はA4縦・3列で、各行はシールの実寸幅を指定間隔で詰めます。列数分そろった行は中央配置し、列数に満たない最終行は左余白から配置します。1行を途中で分割せず次ページへ送ります。行幅は`シール幅合計 + 間隔 × (行の枚数 - 1)`で判定し、収まらない場合は超過量と設定可能な片側余白の上限を表示します。プレビューとPDFは`app/services/print-layout.ts`の同じ配置結果を使用し、PDF座標はミリメートルからポイントへ換算します。

## Undo／Redo

`useHistory`は`CardProject`のJSON互換スナップショットをpast／futureへ保持します。画像、Blob、フォント、選択状態は履歴へ入れません。

再検出の混在適用だけは、変更したOCR候補の適用前後も履歴の各操作に付随させます。全候補を通常スナップショットへ混ぜず、通常の領域編集では候補を変更しません。付随変更はカード別退避・履歴上限・Redo分岐と同じ寿命を持ち、検証・Store更新に失敗した場合は履歴を進めません。候補の単独レビュー履歴と、通常の候補確定・破棄の仕様は維持します。

- 領域の追加、移動、サイズ変更、設定変更を履歴化する
- ポインター移動中ではなく、操作の確定単位で履歴を追加する
- 手動マスクは1ストロークを1操作として扱う
- アセット編集はカード編集履歴の対象外とする
- カード切り替え時はカードIDごとに履歴を退避・復元し、別カードの履歴を混在させない

カード別履歴は実行中だけ保持し、プロジェクトには保存しません。全カードへ波及する変更などで退避時と異なるカード状態を検出した場合は、古い履歴による上書きを避けるため、そのカードの履歴をリセットします。

初回保存時は編集中のカードと履歴に保存先のカードIDを紐付け、選択とUndo／Redoを維持します。保存は開始時点のスナップショットを対象にし、完了時に最新の編集状態を上書きしません。未保存判定は実際に書き込んだ内容と比較し、未保存アセットBlobも書き込んだものだけを解放します。保存・読込・カード追加中は操作を止め、競合する処理の開始を防ぎます。

### Store・履歴・候補・保存の同期契約

| 操作 | 正規データへの反映と所有 |
| --- | --- |
| 通常領域の編集・Undo/Redo | `useCardEditor`がカードID付きで`projectStore.updateCard`へ通知。履歴は編集データのみを持ち、候補や画像を含めない |
| 再検出の混在適用・Undo/Redo（UI未接続） | `applyRegionDetection`が変更候補だけを履歴に付随させ、`applyCardCandidateEdit`で領域・候補・所属を一回で置換。後続の対象候補編集は競合として停止し、未選択候補は保持 |
| 候補の移動・分割・チェック・候補Undo | 表示コピーを`useCandidateReview`→一括OCRの更新窓口→`setCardOCRCandidates`へ反映。Storeは認識行も含めて独立したコピーを持つ |
| カード切替・保存済み候補の復元 | Storeの候補から新しい表示コピーを作り、候補の編集履歴をリセット。通常領域はカード別履歴を復元 |
| 候補の確定・破棄 | 確定は選択候補を通常領域の1操作として追加。両方ともレビュー対象候補をStoreから除き、通常領域Undoでは候補を復活させない |
| 保存開始 | `captureProjectSave`がStoreのplain dataを複製し、削除対象と書込Blobの対応を控える。ブラウザ資源はJSONに入れず、Blobは同一性の照合用に参照を控えるだけ |
| 保存完了 | `acceptSavedProject`は最新編集を維持して保存済み画像パスと削除分を反映。runtimeは書き込んだBlobと同じものだけ承認。保存署名は書き込んだ文書から作る |

`useProjectPersistence`は開始・承認・画面通知を、`services/project/save-snapshot.ts`は保存対象の確定を、`folder.ts`は実I/Oを担当します。I/Oは新アセットパスへの画像書込→旧JSONのバックアップ→新JSON→不要画像の削除の順を維持します。JSON/バックアップ失敗時は新パスだけを掃除し、元画像を上書きしません。初回保存でも画像を先に書き、保存成功時の履歴へのカードID紐付けを維持します。

別プロジェクトの画像とアセットは先にデコード・検証し、成功後に現在の状態を切り替えます。失敗した場合は準備中の画像を解放して現在の作業を維持します。カード追加時も未保存アセット画像をJSONより先に書き込みます。

未保存のカード編集・PDF作業から離れる際は`useUnsavedChanges`のルートガードで確認モーダルを表示します。作業切替、ホーム、ブラウザの戻る操作を同じ経路で扱います。タブ終了・再読み込みは`beforeunload`によるブラウザ標準の確認を使います。PDFは作業プロジェクトJSONの保存・復元時点との差分を未保存として扱います。

## project.jsonの検証と移行

`app/services/project/format.ts`は公開窓口を維持し、内部を`format/`へ分割しています。`codec.ts`が読込・書出し順、`migrations.ts`が旧versionの補完、`regions.ts`と`entities.ts`が値の正規化、`integrity.ts`が項目・複雑さの検証、`paths.ts`が相対パス、`values.ts`が基本値の判定を担当します。フォルダI/O・ブラウザ資源・Storeには依存しません。

読込は容量確認→JSON解析→移行→複雑さ検査→version/文書形状→項目検査→正規化の順です。書出しは現versionと複雑さ・項目を検査したうえで、渡された保存データをJSON化します。読込時の既定値補完を保存データへ黙って再適用せず、プロパティ順・末尾改行も従来どおりです。

- 現行形式はversion 4。カードごとの任意フィールド`ocrCandidates`へ未確定OCR候補を保存し、独立した任意フィールド`assetDiscovery`へアイコン候補・個別承認・グループを保存する。アイコン収集・確認画面はまだ未接続
- version 0とversion省略形式はversion 1相当に補完し、version 1とともに印刷設定等を補ってversion 4へ移行する。version 2・3は既存設定を保持し、アイコン候補なしでversion 4へ移す。version 4以外に`assetDiscovery`が混在する文書は黙って破棄・採用せず拒否する
- アイコン候補は1カード100件・全体2,000件まで。カード・アセット・所属・グループの参照、元画像座標、承認時の矩形と画像ハッシュを読込・書出しの両方で検証する。JSON全体は読込・書出しとも20 MiB以下
- 候補の矩形は保存した検出元の画像寸法で検証する。現在画像の寸法と異なる旧候補は、承認・所属なしの再確認用データとして保存できる。元画像に合わせた矩形の自動拡縮・切捨ては行わない
- 未知の将来versionは推測せず拒否する
- 絶対パス、空要素、`.`、`..`を含むパスを拒否する
- Blobやフォント本体をJSONへ含めない
- カード、領域、保護領域、アセット、フォント、OCR辞書、用語集の空IDと重複IDを拒否する
- CSV照合に使うカード内の`regionId`と、インライン参照に使うアセット名の重複を拒否する

旧形式の省略可能フィールドには既定値を補います。主要コレクションに不正な項目がある場合は黙って除外せず、該当箇所をエラーとして画面へ通知し、プロジェクト全体の読込を中止します。自動修復で意図しないデータを破棄しないための選択です。破棄候補を利用者が確認して選択できる復旧UIは未実装です。

保存時は上書き前のJSONを`project.backup.json`へ退避します。カード画像は新しいJSONの保存成功後に削除し、参照整合性を優先します。

アイコン候補はStoreの`setAssetDiscovery`で検証・複製し、初回保存前は下書きとして保持します。保存署名と保存開始スナップショットにも含め、保存中の候補編集は未保存のまま残します。領域候補の確定では生成した領域IDへ所属を対応付け、領域削除・縮小・Undoや候補破棄では無効な所属だけを解除します。アセット削除では登録先・承認を解除して候補を残し、カード削除確定では候補とグループ参照を同時に除きます。これらの操作では`sourceIcons`・原文・訳文を変更しません。再承認UI・アセット支援再解析の接続は別の実装段階です。

`useDiscoveryImageIdentity`は候補がある場合に、表示中カードの元ファイルと候補が参照するアセットPNGを端末内のWebCrypto（SHA-256）で逐次照合します。未保存PNGを保存済みファイルより優先し、保存成功後もruntimeが同じPNGを照合元として保持します。ファイル名・更新日時・同じアセットIDだけで同一画像と判断しません。同じBlobの処理はWeakMapで共有しますが、失敗はキャッシュしません。プロジェクト世代・ファイル・カード・候補状態の変更や破棄後は遅延結果を捨て、取得時にも照合元が現在のものか検証します。読込失敗は「削除」と区別して未確認とし、未表示カードの原画像を一括デコードしません。保存・読込中は待機し、読込完了後の承認失効を未保存として残します。外部送信は行いません。

`services/asset-discovery/collect.ts`はUI非依存の候補収集入口です。OCR直後は実測行・単語を受け取り、再抽出では保存領域の枠と近傍を新しくOCRします。編集済みの保存行座標は流用しません。領域のないカードは全画像をOCRしますが、アイコン探索は得られた本文行の近傍に限定します。再OCRは最大256個の領域から重なる範囲を結合し、32範囲・元画像換算400万画素・1,000行・10,000単語で制限します。上限到達や不正な領域は検出なしと区別して返します。抽出理由は任意の`detectionReason`として保存でき、既存のversion 4文書で省略されていても読めます。

アイコン抽出の端部は`adjacent-text.ts`で隣接字形を避けます。実測した本文高さの0.65〜1.25倍・幅1.25倍以下・行中心差0.35倍以下の明暗成分について、信頼度65以上の英数字を含むOCR単語内に80%以上収まるものを手掛かりにします。字形の中心が切り抜き枠の外にあり、検出の核を削らずに離せる場合だけ左右端を詰めます。数字とアイコンが一つのOCR単語でも単語全体は除外しません。薄い外周を補完した場合はその輪郭も保護するため、すべての隣接文字を除去できる保証ではありません。検出器改訂は`components-v4`で、ゲーム固有の語句・座標は条件に含めません。既存の保存候補・登録PNGを自動で切り直す処理ではありません。

`services/asset-discovery/batch.ts`はカードと設定の開始時スナップショットを一枚ずつ処理し、候補・一時的な比較特徴・類似グループ案を返します。個別失敗でも完了済みの提案は保持し、キャンセル・対象変更後の現在カードの提案は採用しません。Storeへの追加・既存候補の置換・承認・既存領域の変更は行いません。呼出元が空き候補数と対象の有効性を提供し、再抽出の差分確認・保存とUIへの接続を担当します。この接続は未実装です。収集処理が作るBitmap、特徴計算のCanvas、OCR用Canvasは処理後に解放し、共有OCR Providerの寿命は呼出元が管理します。

類似グループ提案は`services/asset-discovery/group.ts`と`similarity.ts`で行います。単色の図形は既存の形状・色スコアを使い、内部に模様がある場合は12×12に縮小したRGB配置の相関を比較します。±1セルの平行移動だけを許容し、平均色・縦横比・輪郭の事前検査、両画像に対して70%以上の共通不透明度、共通部の模様の存在を要求します。同じ外形でも内部の記号が違う候補は分離します。閾値0.9は正解確率ではなく、確認前の提案基準です。全メンバーとの一致を要求し、連鎖的な統合を避けます。比較用特徴のキャッシュは一回の提案内だけで、PNG・保存候補・個別承認は変更しません。最大2,000候補・既定10,000比較で打ち切りを通知し、未比較の候補も単独グループとして残します。既存の手動アイコン照合・登録PNGの透明化処理は変更していません。

登録済みアセットへの一致提案は`services/asset-discovery/asset-catalog.ts`と`asset-matches.ts`で行います。保存待ちPNGを優先して実バイトのSHA-256と比較特徴を取得し、現在の候補矩形を元画像から再計測して照合します。アセットを逐次デコードし、既定256画像・1カード10,000比較で制限します。既定の類似度閾値は0.9、上位2件の差が0.03以下なら曖昧とし、最大5件を提案します。未読込・デコード失敗・件数上限による未比較を「一致なし」と区別し、除外候補は照合しません。提案は関連付け・承認・原文の変更を行わず、選択された一件も適用前に現在性を再検証します。呼出元はプロジェクト世代・元File・コレクション差替え・取消を照合し、サービス内でも枠・判断・登録先・PNG参照の変更を検出します。一度失効を検出した提案は同じ値へ戻っても復活させません。特徴と提案はセッション内だけに保持し、保存JSON・Undoへ入れません。これはUI非依存の照合入口です。

`features/cards/useDiscoveryAssetMatching.ts`は表示中カードの一致提案を管理し、明示選択を`useDiscoveryReview.linkAssetChoices`へ接続します。複数候補に別々の登録先を選んだ場合も、全件を先に検証して一つのレビューUndoにまとめます。一部の選択が不正なら部分適用せず、未選択の出現箇所・グループ・原文・訳文・描画データには触れません。登録先を変えた出現箇所は再確認待ちになり、承認は別操作です。適用後は古い提案を破棄します。同期監視でカード・元画像・PNG・候補状態・要求世代・処理可否の変更を検出し、同一tick内の変更→Undoでも以前の提案を採用しません。取消後の遅延完了は新しい照合を消さず、照合失敗・関連付け失敗は既存データを保って再試行できます。通常画面から呼び出す確認UIは未実装です。

`services/asset-discovery/review-operations.ts`はレビュー操作を検証済みの独立コピーへ適用します。手動追加・範囲修正・登録先変更・除外／復帰・個別承認・所属確認と、グループ移動／統合／分割・代表／名前／登録先提案の編集を扱います。手動候補も保存と同じ件数・座標・参照制約に従い、範囲修正や承認時は現在の画像内容との一致を要求します。グループ整理は個別の承認・登録先を変更しません。このサービスはStore・履歴・PNG登録・確定領域を変更しないため、操作UIとレビュー専用Undoへの接続が別途必要です。

`features/cards/useDiscoveryReview.ts`は上記の操作を`setAssetDiscovery`へ接続し、レビュー専用Undo/Redoを管理します。履歴は候補JSONだけを最大30操作・合計200万UTF-16コード単位までセッション内に保持し、上限による古い履歴の打切りを通知用フラグで返します。通常領域の履歴や共有アセットPNGには触れません。無変更操作は履歴を増やさず、通常の保存・アセット改名・本文変更では履歴を維持します。候補自体の外部変更、カード／所属先の座標・参照変更、アセット削除や、呼出元が渡すプロジェクト世代・元File・PNG改訂の変更では古い履歴を破棄します。失われた承認をUndo/Redoで戻す場合も現在の画像ハッシュを検証します。Storeの文書取込みでも候補をパーサーの正規形へ揃え、キー順だけで保存署名や無変更判定が変わることを避けます。この接続処理のStoreテストはありますが、通常画面から呼び出すレビューUIは未接続です。

`services/asset-discovery/proposal-review.ts`は再抽出したアイコン候補を新規・変更・変更なし・未検出・対応要確認・元画像変更に分類します。現在の枠と初期検出枠を対応の手掛かりにし、手動調整を別候補として追加しにくくします。1対多・多対1と新候補同士の重なりを明示し、相互に一意でない対応を自動置換しません。選択した新規追加／明示した既存候補への置換だけを独立コピーへ適用し、候補ID・登録先・グループ・除外判断は保持します。範囲や元画像を変えた候補の承認は解除します。未検出を削除に変換せず、未選択の手動調整も保持します。比較の基準値はWeakMap、表示値は凍結した独立コピーとしてセッション内にだけ保持し、PNG・比較特徴・未適用差分を保存JSONへ入れません。`useDiscoveryReview`の比較／採用入口はセッション・操作世代にも結び付け、編集→Undoや画像差替え後に以前と同じ値へ戻っても古い比較を採用しません。差分採用は一回のレビューUndoで取り消せます。これはアイコン候補の比較であり、通常の文字領域を再検出する差分UIとは別です。

`features/cards/useDiscoveryAssetRegistration.ts`は、表示中の候補の元画像ハッシュ・寸法・代表指定を確認して、既存の`useEditorAssets.createSourceIconAsset`へ代表切り抜きのPNG登録を依頼します。代表用の切り抜き矩形と各出現箇所の矩形は別に保ち、登録後は選択した代表の登録先とグループの登録先提案だけを更新します。他のメンバーや`sourceIcons`・原文・訳文・マスクは変更せず、代表自体も別途承認が必要です。新規PNGはruntimeの保存待ち画像に置き、ファイル書込は従来どおりプロジェクト保存時です。関連付けは`useDiscoveryReview.linkAsset`で一つのUndoにまとめますが、共有アセット登録そのものはUndoしません。登録途中の取消・対象変更は遅延結果を捨て、取消／失敗した作業Canvasを解放します。登録完了後に対象が変わった場合や関連付けだけが失敗した場合は、共有PNGを消さず部分成功と警告を返します。通常画面から呼ぶ登録・レビューUIはまだ未接続です。

`services/asset-discovery/source-ocr.ts`は、選択された承認済み出現箇所を領域の独立コピーへ足し、原文候補と明示適用用のパッチを返します。既存の手動アイコンは保持し、同じアセット・同じ矩形は重複追加せず、重なり・所属不明・画像寸法や承認の不一致・アセット名や参照の不備は停止します。元画像・利用アセットPNGの実バイトのハッシュと、それに対応する画像の取得・寿命管理は呼出元の責務です。比較基準はWeakMap、作業コピーとプレビューは凍結し、保存JSON・通常Undoには入れません。

再OCRはコピー上のアイコンと保護領域だけをOCR画像から除外し、3倍・余白12pxの単語座標から原文タグを生成します。単語座標欠落・不正値・予期しないアイコン記法は自動置換で補わず拒否し、1万単語と既存の原文長上限で制限します。拡大・余白追加後の寸法もCanvas確保前に既存の画像上限で検証します。認識前後・進捗・適用直前に対象、個別承認、利用アセットのメタデータとハッシュ、呼出元のセッション・編集世代を確認し、取消・変更後の遅延結果を破棄します。呼出元は編集→Undoなど元の値へ戻る変更でも世代を進める必要があります。共有Providerと元画像はこのサービスでは解放しません。

位置のみのパッチと、位置＋原文のパッチは別です。後者を既存の`updateRegion`へ一度で渡すことで一度のUndo/Redoにまとめ、訳文を維持しつつ原文変更時の翻訳状態は従来のルールに従います。`updateRegion`は任意の期待カードIDを受け取り、実際の編集先と異なる場合は書込み・履歴更新前に拒否します。適用前の失敗・取消ではStoreや描画を変更しません。

`features/cards/useDiscoverySourceOCR.ts`は、runtimeの元Fileと使用するPNGの実ハッシュ取得、準備、再OCR、明示適用をつなぎます。PNGは保存待ちを優先し、手動指定済みアイコンのPNGも照合します。準備時にも元Fileをデコードして実寸法を確認し、位置だけの適用ではProviderを初期化しません。確認待ちの間はBitmapを保持せず、再OCR時に同じFileを再度デコードし、成功・失敗・取消時に解放します。共有Provider・アセット画像は解放しません。

同フローは同期監視と適用直前の検証で、編集→Undo、元File・使用PNGの差替え、カード・選択領域・プロジェクト世代・依存設定・外部処理状態の変更を検出して古い案を破棄します。グループ名だけの変更や同じPNGの保存待ち→保存済み移行は有効な案を失効させません。原文と位置が同じ場合は通常Undoを増やさず、OCR失敗時にまだ有効な位置案は再試行・位置のみの明示適用に残します。実ハッシュ取得から共通描画・通常Undoまでの合成画像によるブラウザ結合テストがありますが、通常画面のプレビューUIと利用者向け適用ボタンは未接続です。

## OCRと翻訳の差し替え境界

検出の内部設定は`app/services/ocr/detection-settings.ts`を入口に、画像補正、候補生成（`candidates/settings.ts`）、黒文字測定（`heading-settings.ts`）に分離しています。`detectRegions`へ呼出し単位で渡し、単体・一括の既定結果は維持します。装飾除去・大文字ラベル分類・行結合・中央黒文字測定の組込ポリシーの選択、フィルター・初期チェック・余白・色閾値・局所OCRの制限を変更できます。細かな誤読パターンと形状の安全条件は各実装内に残し、任意コードは実行しません。これは信頼された内部コード向けの型で、外部JSONの入力検証・UI切替・インポート・保存は未実装です。特定ゲームの専用プロファイルは同梱しません。[分離範囲と非公開プロファイルの検討](verification/ocr-settings-separation.md)を参照してください。

OCRは`OCRProvider`を介します。現在の`TesseractOCRProvider`は英語モデルをブラウザ内で実行し、Worker、WASM、学習データを同一アプリから読み込みます。複数行の結果は行の座標から上→下、同一行は左→右へ並べ直します。OCR結果は候補として表示し、自動で原文を上書きしません。

全画像の検出経路は`services/ocr/detect-regions.ts`へ集約しています。単体と一括は同じ前処理・Provider認識・画像補正・候補生成を呼び、候補と元の検出行数を受け取ります。サービスはStore・Vue状態を持たず、画像やWorkerの解放は呼出元に残します。`isCurrent`で対象破棄後の進捗・結果・失敗を破棄します。一括中止はこれとは別で、追加の見出しOCRを止め、現在カードの結果を確認用に残して次カードへ進む前に中止する既存動作を維持します。

候補生成の公開窓口は`candidates.ts`のまま維持し、内部を`candidates/normalize.ts`（見出し・画素補正と縮尺復元）、`filter.ts`（採否・初期選択）、`headings.ts`（装飾除去）、`grouping.ts`（横・縦結合）、`geometry.ts`（外接枠・余白・重なり調整）に分けています。補正済み行を識別するWeakSetは1回の候補生成内だけで使います。保存候補と認識矩形の正規の型は`types/ocr.ts`へ置き、Providerの入出力・実行オプションから分離しています。既存の`services/ocr/types.ts`からの型exportも維持し、保存JSONのフィールドやversionは変えていません。

候補生成は信頼度0%の行を結合前に除外し、0%より高く40%以下を未選択で残します。同一行の本文断片は、信頼度・語数・アイコンの重なりを条件に選択状態が異なっても結合します。個別・一括検出は共通の`region-image.ts`で原画像を確認します。`pixel-regions.ts`は明るい文字の行と色付きアイコンを別々に測り、OCRの過大な行枠を補正します。高信頼度の単語の横幅と本文内の記号座標も保護します。

明るい帯は画像の連結成分から探索し、最大10箇所を同じローカルOCR Providerで単一行として再認識します。短い大文字ラベル・信頼度・位置を検証して、既存見出しを置換または未検出の見出しを追加します。信頼度は局所OCRの実測値です。確認済みラベルは白文字用補正から除外し、文字端の二重縮小を避けます。`heading-bounds.ts`は帯の切り抜きと既存の装飾除去を補助します。画像解析は長辺1200pxを上限とし、画素・Canvas資源を保存データに混ぜません。判定不能・Canvas非対応時はOCR枠を維持し、追加OCR失敗は診断ログへ記録して全体OCRへ戻します。非同期の各境界で対象の有効性を確認します。外部通信は追加しません。

複数カードのOCRは領域未作成カードをキューへ入れ、同じWorkerで1枚ずつ順次処理します。原寸画像は処理中の1枚だけを`ImageBitmap`として保持して完了時に閉じます。個別・一括どちらの未確定候補も、`useProjectStore.setCardOCRCandidates`からカードの`ocrCandidates`へ反映し、未保存判定と`project.json`の保存対象に含めます。初回保存前はStoreの`draftOCRCandidates`に保持し、初回保存時にカードへ移します。

見出し補正には、左側だけが低信頼度の記号となった複数語ラベルも含めます。少なくとも2語の高信頼度な大文字語と全体の信頼度・配置を条件にし、末尾の句点誤認を補正します。画素による左右の補正は文字行の暗い低彩度画素から行い、単語間の空白を許容しつつ、小さい孤立した端の装飾だけを除外します。大きな別の文字群がある場合は左右を縮めません。

1語と片側の記号からなる見出しは、語の信頼度80%以上、記号40%以下、記号の大きさ・縦横比・距離を条件に補正します。OCR行と単語の照合は完全内包ではなく単語中心の内包と単語面積65%以上の重なりを使い、集めた単語の文字列が元の行と一致することも要求します。これにより行枠からはみ出した単語を保持しつつ、隣の本文の混入を抑えます。

候補生成の最後に、横方向に重なりがあり、認識行の外接矩形は上下に離れている候補対の余白を調整します。認識内容間の中央を基準に余白だけを縮め、空きがあれば最大1pxの隙間を残します。認識行・原文・信頼度・選択状態は変えず、認識枠自体が重なる場合や別の段組みは変更しません。

先頭語へ装飾が融合し、末尾の飾りが数字・記号化した複数語見出しは、先頭語が低信頼度、後続2語以上が高信頼度、大文字語群の平均信頼度60%以上、末尾記号の寸法・位置等を条件に、画素補正を試します。左端と高さの両方が十分に縮む裏付けがある場合だけ末尾の誤認を除去します。低信頼度の先頭語は保持します。行下辺の薄い低信頼度罫線は単語照合から除きますが、元の行テキストとの一致条件は維持します。

候補のID・枠・原文・信頼度・追加対象のチェック状態・認識行を保存します。画像等のブラウザ資源と候補編集のUndo履歴は保存しません。`useBatchOCR`はカード別の候補と確認待ち状態をStoreから導出し、処理中・失敗・待機等の実行状態だけをセッション内に持ちます。通常領域のUndoスナップショットには候補を含めず、現在の画面での候補変更の取り消しは表示中の候補履歴で扱います。再検出の混在適用向けには、変更候補だけを通常履歴に付随させる別の入口を用意しています（UI未接続）。読込・カード切替時に保存済み候補をOCRパネルへ復元し、追加・破棄時には永続状態からも除去します。保存成功時は保存中に加わった変更を上書きしません。

`app/services/ocr/candidate-format.ts`が候補IDの重複、座標・寸法・信頼度・チェック状態・認識行の形式と件数を検証します。不正な候補は黙って削除せず読込・保存を拒否します。画像寸法の変更時は古い候補を無効化します。個別検出の遅延結果もカードIDと画像インスタンスを照合し、対象が変わった場合は保存状態へ反映しません。

再検出差分の純粋処理は`services/asset-discovery/region-proposal.ts`です。確定領域と未確定候補を一緒に比較し、位置に基づく対応案と比較用の旧原文・検出文字列を返します。表示値は独立コピーを凍結し、基準値はWeakMapへ保持します。呼出元が確認した元画像SHA-256・レビューのセッション識別子・編集世代を適用時にも照合します。未検出の領域は削除せず、曖昧な対応は選択された一つの修正先だけを扱い、自動統合・分割は行いません。新規追加も明示操作で未確定候補へ追加し、確定は従来の別操作に残します。検出候補同士の重複と既存領域への二重追加を拒否し、比較仕事量は既存件数×検出件数＋検出件数の二乗が100万以下に制限します。

`features/cards/useRegionDetectionReview.ts`は差分の非同期制御と明示適用を担当します。実FileのSHA-256を取得し、呼出元から渡された読取専用の検出処理を実行します。結果はセッション内の差分に留め、選択された枠修正・新規候補だけを`applyRegionDetection`へ渡します。画像・プロジェクト世代・対象カード・領域・候補・編集状態と追加の検出依存先を同期監視し、変更後にUndoで元へ戻しても古い差分を復活させません。取消後の遅延完了・失敗は新しい要求を変更せず、対象が有効な検出失敗・適用失敗は呼出元へ通知して再試行できます。下書きと保存済みカードの両方を扱い、適用入口でも期待する編集カードIDを照合します。通常画面の検出処理・差分UIには未接続です。単体テストの模擬結果に加え、合成PNG・実ローカルOCR・実Store・表示コピー・Undoを接続したブラウザ結合テストがあります。

`services/ocr/detect-file-regions.ts`は、ハッシュ確認したFileを`createImageBitmap`で読み、共通の`detectRegions`へ渡す読取専用の入口です。ハッシュ計算はレビュー制御側が担当し、同じ不変Fileを渡します。ファイル容量と予定寸法を先に検証し、デコード後の実寸法が一致しなければOCRを始めません。未対応環境は明示的に停止し、外部サービスへ転送しません。Bitmapは成功・失敗・取消のすべてで解放し、呼出元が所有するOCR Providerは終了しません。古い結果だけでなく進捗・補正通知も破棄します。設定・実測座標の取得指定は共通検出へ渡せますが、保存済み候補・領域を直接更新しません。

枠修正ではID・原文・訳文・翻訳状態を保持し、`rebaseRegionBounds`でアイコン・保護範囲・手動マスクの元画像上の位置を維持します。関連データの欠けやマスク描画範囲の変化は切り捨てで解決せず拒否します。未確定候補はチェック状態・文字列・信頼度を保持し、表示・分割用の行座標だけを新しい枠へ拡縮します。この行座標は実測OCRとして流用しません。全選択を独立したカードコピーへ適用するため、後半の選択が失敗しても入力に部分適用しません。実OCRから比較・混在編集入口へ渡す経路も合成画像のブラウザ結合テストで確認していますが、通常の検出ボタンと差分UIへの接続は別途必要です。現行画面の再検出動作を変更したものではありません。

確定領域だけの枠修正を受け取る編集入口は`useCardEditor.applyRegionBounds`です。選択した複数領域の関連座標を全件検証してから、一回の通常履歴commit・Storeへの通知にまとめます。一件でも枠や関連座標が不正ならcommitせず、無変更では通知・Undo追加・Redo破棄をしません。通常の領域編集と同じカード別履歴でUndo/Redoでき、未確定候補や共有PNGは変更しません。

混在編集入口の`useCardEditor.applyRegionDetection`は、確定領域の枠修正と候補の修正・追加を全件検証し、`projectStore.applyCardCandidateEdit`へ一回で渡します。Storeは現在の領域・候補との一致を再確認し、文書または下書きの領域・候補・所属参照を一回の置換で反映します。下書きもこれら三つのデータを一つの内部状態で所有し、同期監視へ途中状態を公開しません。通常履歴には変更候補の適用前後だけを付随させ、無関係な候補の後続編集はUndo/Redoで巻き戻しません。対象候補が変更・確定・破棄された場合は古い履歴で上書きせず停止します。枠変更で無効になったアイコン候補の所属は解除し、Undoで枠が戻っても自動再所属させません。候補自体・承認・共有PNGは削除しません。保存側で変更された候補の表示コピー・専用候補履歴は`useCandidateReview`で同期します。差分UIからの呼出しと競合時の画面案内は未接続です。

翻訳は`TranslationProvider`を介します。通常フローは手動入力とCSVです。Translation Endpointはα機能で、APIクライアントの単体テストとローカル翻訳モックとのブラウザ結合動作を確認済みです。静的公開版（`pnpm build:static`で生成）では無効化します。

Provider境界は実装の差し替えを可能にしますが、他のOCRエンジンや翻訳サービスへの直接接続が実装済みという意味ではありません。

## 複数カードと共有参照

カードの領域はカード単位、アセット・フォント・OCR辞書はプロジェクト単位で所有します。

共有アセットの名前を変更すると、表示中カードだけでなく全カードの`[icon:name]`と出現箇所設定を更新します。削除予定カードも保存確定まではプロジェクト内に残すため、参照更新の対象です。

出現箇所ごとのアセット設定は、アセット名と同名トークン内の出現順を使ってテキスト編集後の位置へ追従します。対象トークンを削除した場合は対応設定も削除します。同名トークンの順番を入れ替えた場合は、利用者による確認が必要です。

## 翻訳レビュー

`useTranslationReview`がカード横断の確認画面、CSV取込・出力、反映操作を接続します。`TranslationReviewDialog`で訳文を編集し、`app/utils/translation-review.ts`が行モデル・確認事項・反映前の原文と訳文の照合を扱います。選択した変更だけを下書きとして反映し、一部反映では未選択の編集を保持します。自動候補取得はサンプル翻訳に対応し、通常のTranslation Endpointは個別の送信確認を使用します。

## CSV照合

プロジェクト全体の翻訳CSVは`card_id + region_id`を照合キーにします。カード名、表示名、原文は確認情報で、反映するのは訳文だけです。

- 未一致行を反映しない
- 同じキーの重複行は後の訳文を採用し、件数と行番号を表示する
- CSV出力後に原文が変わった行を表示する
- 適用前に確認画面を表示する
- 削除予定カードを対象外にする

従来のカード単位CSVには`card_id`がないため、現在選択中のカードだけを対象にします。

PDF用CSVは`pdf_name + text_id`を照合に使い、PDF名不一致、重複、原文差分を別に数えます。

## ブラウザAPIと制約

- File System Access API: プロジェクトフォルダの読み書き。メインのカード編集で必要
- Local Font Access API: インストール済みフォントの列挙。未対応時はフォントファイル選択を利用
- IndexedDB: 選択したフォントBlobの再利用
- Canvas／ImageBitmap／Object URL: 画像処理とランタイム保持
- File API: PDF、CSV、画像、フォントのユーザー選択

これらのAPIはクライアントでのみ利用します。フォルダ権限はセッションをまたいで保持しません。対応ブラウザの詳細はREADMEを参照してください。

## PDF処理

`/pdf`は現在「準備中」の案内のみを表示し、以下は保持している編集実装の説明です。カードのA4面付けPDF出力は引き続き利用できます。

`app/features/pdf/PdfEditor.vue`が文書の採用と画面間の調整を担当し、次のcomposableへ状態と寿命管理を分離しています。解析・変換・入出力の実処理は`app/services/pdf.ts`と`app/services/pdf-project.ts`にあります。

- `usePdfPreview`: ページ画像とObject URLの所有・解放、古い描画結果の不採用
- `usePdfEntryEditing`: 項目の選択・原文修正・順序変更・結合・分割
- `usePdfOCR`: OCR Workerと実行状態、文書・ページ変更後や破棄後の結果の不採用
- `usePdfProcessing`: 解析・復元・書き出しの実行状態、進捗、AbortController。中止要求後も処理完了までは次の開始を拒否

PDF.jsでテキストレイヤーを解析し、pdf-libで元PDFへ背景パッチと訳文を追加します。利用者がTTF / OTFを選んだ場合は`@pdf-lib/fontkit`で使用文字のサブセットを埋め込み、検索・選択可能なPDFテキストとして描画します。フォント未選択時はCanvas描画した画像文字へフォールバックします。ページ全体を画像化しないため、対象外のテキスト、図形、画像、ページ寸法を維持できます。解析時のviewport変換行列とページ回転角を保持し、表示座標とPDF描画座標を相互変換することで、90度単位の回転、CropBoxの原点・寸法、MediaBoxとの差を反映します。解析と書き出しはページ単位で進捗を通知し、`AbortSignal`によってページ処理の境界で中断できます。PDF.jsのページオブジェクトと背景画像は成功・失敗・キャンセルのいずれでもページごとに解放し、後から追加したOCR項目もページ番号で安定ソートして同じページを繰り返し描画しません。元PDFのArrayBufferもpdf-lib用とPDF.js用に必要な分だけ読み、明示的な複製を避けます。ページ数にはハード制限を設けませんが、100ページを超える場合はPDF.jsが文書情報を取得した直後かつ各ページの解析前に続行確認を挟みます。pdf-libは出力文書全体をメモリへ読み込むため、処理可能な規模はPDFの容量、画像量、文字項目数、ブラウザのメモリに左右されます。捕捉可能な`RangeError`やメモリ確保エラーは共通メッセージへ変換しますが、ブラウザプロセス自体の強制終了は捕捉できません。プレビューでは抽出原文と同一ページ内のCSV出力順を修正し、連続項目の外接矩形への結合と、改行単位で縦方向に等分する分割ができます。結合・分割では先頭項目のIDを維持し、新規項目に衝突しない派生IDを付けます。CSV対象外にした文字行はCSV出力とPDF差し替えの両方から除外します。

一方、元文字の描画命令は削除せず視覚的に覆います。フォント未選択時の訳文は画像なので検索できません。PDF用フォント本体もサイドカーJSONへ保存しないため、再開後は再選択が必要です。任意角度の文字回転、縦書き、複雑な背景、フォーム、注釈などは制約として残っています。

パスワード要求はPDF.jsの`PasswordException`を分類して読み込みを拒否します。各ページの注釈を`Widget`（フォーム）、`Link`、その他に分類して解析結果へ件数を保持し、UIで互換性警告を表示します。pdf-libで既存PDFへ追記するため対話機能は編集対象にしませんが、出力後の動作確認を利用者に求めます。

画像ページのOCRはページ全体を対象にせず、プレビュー上で利用者が指定した矩形だけをページ画像から切り出してTesseractへ渡します。OCR結果は`p####-o####`形式の安定IDと選択矩形のPDF座標を持つ通常の文字項目へ変換するため、CSV入出力、除外、原文修正、背景補修、訳文配置の既存経路を共用します。
