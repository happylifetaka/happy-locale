# CardEditor.vue追加改善計画

作成日: 2026-09-16
状態: 工程0〜6完了・工程7と最終評価は未完了

## 目的と基準

[前回の分割計画](./CARD_EDITOR_REFACTORING_PLAN.md)で、`CardEditor.vue`を3,993行から1,936行へ縮小した。
次は残った処理の分割に加え、親が中継している共有状態とイベントを整理する。

改善の基準は以下とする。

- 機能を修正する際に読む範囲が絞れる。
- 状態の所有者と更新経路が明確である。
- 親を経由するだけのprops・イベントが減る。
- 編集履歴、保存形式、非同期処理、画面操作を維持する。

直前の検証結果は全437テスト、型検査、lint、ビルド成功。
Playwrightの3テストとユーザーによる日本語IMEの手動確認も成功している。
実装開始時には作業ツリーとテストを再確認する。

## 状態の所有と更新ルール

| 状態・処理 | 所有者 | 方針 |
| --- | --- | --- |
| 保存する文書・カード一覧・共有設定 | `useProjectStore` | 既存の保存経路を維持 |
| 領域本文・座標とUndo/Redo | `useCardEditor` | 本文や領域を別ストアから直接更新しない |
| 画像・フォント・Object URL | `useProjectRuntime` | 資源の所有と解放を維持 |
| 複数の表示部品が使う編集ツール状態 | 新規`useEditorToolsStore`候補 | 小さく試し、効果を確認して拡張 |
| ダイアログ内だけの入力途中の値 | 各コンポーネント | 局所的な状態はその場で管理 |
| 読込・OCR等の非同期状態 | 各composable | 実行の中止・終了後の無効化も同じ責務で管理 |

Piniaに全機能を集める巨大なエディターストアは作らない。
既存のローカルrefとストアをwatchで双方向同期させず、状態の所有元を一つにする。
ストアの状態を分割代入する場合は`storeToRefs`でリアクティブ性を維持する。

## 共通の作業手順

1. 現状の動作、変更経路、初期化・終了タイミングを確認する。
2. 現行実装に回帰テストを追加し、変更前に通ることを確認する。
3. 重要なガードは一時的な変更でテストの検出力を確認し、必ず復元する。
4. 一つの責務・一つの更新経路ずつ変更する。
5. 対象テストと必要な全体検証を実行する。
6. 結果・行数・依存の変化を記録し、適切な単位でコミットする。

不具合が見つかったら分割を止め、再現テストを用意して修正する。
修正は分割と別のコミットにまとめ、テストが成功してから分割を再開する。
既に合意した範囲の不具合修正は都度の承認待ちにしない。仕様が不明な場合だけ確認する。
期待値の緩和やskipで失敗を解消しない。

- [x] 単純なブラシ設定は状態として公開し、排他制御は`startMaskEditing`等のactionにまとめる。
- [x] CanvasとInspectorの接続箇所をストア参照へ移し、親の中継を削除する。

部品の再利用性が必要な場合は、ストアを読む機能別コンポーネントから表示部品へ渡す構成も候補とする。

## 工程2: v-modelと操作イベントを整理する

工程1で残った親子の値同期を対象とする。ストアで直接共有した項目に、重ねてv-modelを追加しない。

| 接続の種類 | 表現 |
| --- | --- |
| ズーム等、単一の値の同期 | `v-model:zoom`等 |
| 保存・削除・認識などの操作要求 | `@save`、`@remove`、`@recognize`等 |
| 他のモードや状態も変更する操作 | 明示的なactionまたは操作関数 |
| 確定前のダイアログ入力 | 子が下書きを持ち、確定イベントで反映 |

- [x] 単純な代入だけのイベント接続を洗い出し、親子を同時にv-modelへ変更する。
- [x] `defineModel`等を使う場合、親と子で初期値・必須性・型が食い違わないようにする。
- [x] 領域本文の入力は現在の履歴更新・IME・描画遅延の経路を維持する。
- [x] 取消可能な入力が確定前に親へ反映されないことを確認する。
- [x] Playwrightで編集・タブ切替を確認する。IMEの処理経路を変更した場合は実IMEも再確認する。

受け入れ条件: 接続の意味が読み取りやすくなり、代入によって更新時の検証や副作用を飛ばさない。

### 工程0〜1: 状態の棚卸しと変更前テスト

- 呼出元は`app/pages/cards.vue`の1箇所で、同時に複数のCardEditorを表示する利用経路はない。
- ブラシサイズ（初期値28）・モード（paint）はInspectorで変更し、Canvasが描画するストロークに使用する。カード・作業画面・プロジェクト切替では保持し、エディターを閉じて再表示すると初期値に戻る。
- マスク編集と保護領域編集は排他的。開始時はアセット範囲選択も終了する。逆にアセット編集開始・切り出し直しでは両編集モードを終了する（`useEditorAssets`）。

- プロジェクト読込は領域選択を解除し、上記watchによって編集モードを終了する。ブラシ設定は保持する。
- `CardEditor.tools.test.ts`に変更前の5テストを追加。ブラシのCanvasへの反映、モード排他、背景方式変更、カード・画面・プロジェクト切替、保護領域選択、終了後の再表示を確認した。再表示は同じPiniaインスタンスを再利用し、ストア移行後の状態漏れも検出できる準備とした。
- マスク開始時の保護領域モード解除を一時的に外すと、新規テストが失敗した。実装を復元済み。全442テスト、型検査、追加箇所のlint、差分検査が成功した。
