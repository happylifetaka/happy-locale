# CardEditor.vue分割計画

更新日: 2026-09-16

## 目的と進め方

`app/components/CardEditor.vue`（開始時3,993行）の責務を分割し、編集内容・履歴・保存形式・画面操作の互換性を維持する。
既存動作を先にテストで固定し、そのテストを維持しながら小さく抽出する、TDDに近い進め方を採用する。

各工程は次の順序で行う。

1. 対象の既存動作と失敗時の期待結果を列挙する。
2. 分割前の実装に対して回帰テストを追加し、正常に通ることを確認する。
3. テストが意図した退行を検出できることを、小さな一時変更で確認して元に戻す。
4. 振る舞いを変えずに責務を抽出する。必要なら抽出先の単体テストも追加する。
5. 対象テスト、全テスト、型チェック、lint、ビルドを実行する。
6. 結果と未完了項目をこの文書へ記録する。

テストが落ちたら次の抽出を止め、環境差・テストの不備・実装の退行・既存不具合を切り分ける。
アサーションの削除、skip、例外の握りつぶしで通さない。仕様判断が必要な場合は確認し、確定するまで依存する変更を進めない。
リファクタリングとは独立した不具合修正は、原因・変更理由・検証を区別して記録する。

## 状態と依存の境界

- 保存するデータ: `useProjectStore`。
- カード編集とUndo/Redo: `useCardEditor`。
- 画像・フォント・Object URL等の資源: `useProjectRuntime`。
- 機能内の一時状態と非同期処理: 各composable。
- 機能間の接続と画面構成: `CardEditor.vue`。

composable同士の循環依存や、全状態を渡す巨大なcontextは作らない。
必要な参照・操作のみを渡す。外部I/Oは差し替え可能にし、連携テストでは実際のストアと履歴を使う。
既存サービスやutilsの単体テストを複製せず、画面内に残る連携と失敗時の整合性を補う。
