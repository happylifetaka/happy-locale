## P1b / P2の基盤: 実画像の内容照合

- WebCryptoで実ファイルのSHA-256を計算する。サイズ上限をバイト読込前に検証し、同じ不変Blobの処理をWeakMapで共有する。API非対応時は名前・更新日時等による代替ハッシュで済ませず、未確認にする。失敗の再試行を可能にする。
- runtimeが描画用アセットに対応するPNGを保持する。再切り抜き時は旧画像との対応を無効化し、保存中の再編集では新しい保存待ちPNGを優先する。保存済みPNGへの引継ぎ、削除・再読込・画面破棄時の解除も接続した。
- 現在カードと候補が参照するアセットを照合し、内容が変わった承認を失効させる。元画像が変わった場合は所属も再確認へ戻す。候補の矩形・グループ・原文・訳文・消去マスクは変更しない。
- 非同期結果はプロジェクト世代・カード・実ファイル・候補状態と照合し、変更・破棄後は採用しない。読込できない画像は不在や一致とみなさず、未確認の理由を診断へ残す。新規の外部通信はない。
- プロジェクトの読込・保存中は照合を待機させる。読込後に画像変更が判明した場合、承認解除を保存済みの状態として誤認しないことを画面接続テストで確認した。

## P1b / P2: 個別レビューとグループ整理の操作

## P1b / P2: レビュー操作のStore接続と専用Undo

- `useDiscoveryReview`から個別レビュー・手動追加・グループ操作を既存のStore actionへ接続した。通常領域や共有アセット画像を履歴に入れず、候補JSONだけのUndo/Redoを持つ。下書きからの初回保存にも対応する。
- 無変更操作は履歴とRedo分岐を変えず、新しい編集だけがRedo分岐を消す。最大30操作・合計200万UTF-16コード単位で制限し、超過では古い履歴を除いて通知用フラグを返す。編集そのものは保持する。この上限は文字列量の制限であり、ブラウザ全体の使用メモリの保証ではない。
- 通常の保存・アセットの改名／表示倍率変更・OCR文章だけの変更では履歴を保持する。候補の外部変更、領域の参照・座標変更、アセット削除、呼出元が渡すプロジェクト世代や画像資源の変更では履歴を同期的に破棄する。資源が後で以前と同じ参照へ戻っても古い履歴は復活させない。
- Undo/Redoで承認を復元するときは、現在の元画像・アセット画像との内容一致を要求する。未読込・内容不一致なら操作を止め、現在値と履歴を保持して再試行可能にする。グループだけの変更では、既にある同じ承認を未読込だけで失わせないが、判明した内容不一致は拒否する。
- 破棄後・処理中の操作は拒否し、Store書込失敗や不正操作でも履歴を進めない。画面破棄で履歴を解放する。候補状態は保存されるが、セッション内の履歴は保存文書へ入れない。
- 接続テストで、文書取込み時の候補のキー順と更新時の正規化が異なると、Undo後の未保存判定が戻らないことを発見した。`replaceProject`も検証結果の正規形を保持するよう修正し、無変更操作・Undo後の保存署名を回帰検証した。
