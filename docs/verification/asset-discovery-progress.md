## P0 / P1b・P3の基礎: 承認・参照・差分の純粋処理

代表出力の確認待ちの間に、UIやファイル書込を伴わない契約部分を実装した。

- 保存用の出現候補・個別承認・グループのJSON型と、その厳密なパーサー。カード・アセット・所属先・グループ参照、承認スナップショットの一致、矩形・SHA-256形式・件数上限を検証する。旧形式の読込に接続した段階ではない。
- 矩形・アセット変更による承認失効、候補→領域IDの昇格、領域削除・縮小・Undo後の所属解除、カード・アセット削除時の参照整理。
- 未読込の画像と、削除済みであると確認できた画像を区別する。遅延読込だけで承認を消さず、適用時は必要な画像ハッシュがすべて確定していることを要求する。
- 領域を変更しない `sourceIcons` 提案。元画像座標→領域内座標へ変換し、既存の手動指定は残す。同じ指定の再適用は重複させず、別アセットや枠の衝突は確認を求める。
- 領域の相互に一意な対応だけを変更／変更なしに分類し、分割・統合・未確定と確定の重複は対応要確認にする。未検出は削除へ変換しない。
- 枠だけの更新パッチはID・原文・訳文・翻訳状態を含めず、アイコン・保護範囲・マスクの元画像上の位置を維持する。範囲の切り捨てや、枠の拡張で既存ブラシの消去範囲が増える場合は適用を拒否する。

自動検証では、不正な保存入力、再切り抜き・元画像差替え、遅延読込、所属IDの昇格と解除、削除後の文書整合性、重複適用・衝突、曖昧な領域対応、既存編集操作を介したUndo/Redoを対象とする。

## P1b / P2の基盤: 実画像の内容照合

- WebCryptoで実ファイルのSHA-256を計算する。サイズ上限をバイト読込前に検証し、同じ不変Blobの処理をWeakMapで共有する。API非対応時は名前・更新日時等による代替ハッシュで済ませず、未確認にする。失敗の再試行を可能にする。
- runtimeが描画用アセットに対応するPNGを保持する。再切り抜き時は旧画像との対応を無効化し、保存中の再編集では新しい保存待ちPNGを優先する。保存済みPNGへの引継ぎ、削除・再読込・画面破棄時の解除も接続した。
- 現在カードと候補が参照するアセットを照合し、内容が変わった承認を失効させる。元画像が変わった場合は所属も再確認へ戻す。候補の矩形・グループ・原文・訳文・消去マスクは変更しない。
- 非同期結果はプロジェクト世代・カード・実ファイル・候補状態と照合し、変更・破棄後は採用しない。読込できない画像は不在や一致とみなさず、未確認の理由を診断へ残す。新規の外部通信はない。
- プロジェクトの読込・保存中は照合を待機させる。読込後に画像変更が判明した場合、承認解除を保存済みの状態として誤認しないことを画面接続テストで確認した。

この段階では関連9ファイル56テスト、アプリ・テストの型検査、変更ファイルのESLintが成功。実SHA-256の既知ベクトル、同名・同日時の異なる内容、処理の共有・失敗再試行、同一ID再切り抜き、保存中の再編集、カード／プロジェクト切替、画面破棄、改名のみの承認維持を含む。画像の外部差替えは新しいFileの読込時に判明するものであり、OS上のファイル変更を常時監視する機能ではない。

候補の確認・再承認画面と、登録済みアセットを使った再解析・差分適用は未接続。今回の結果をP2・P3の完了とは扱わない。

## P1b: 実測座標からの収集入口・再OCR・逐次キュー

- OCR直後の実測行・単語から候補を生成する入口と、既存領域・OCR候補の枠の周辺を新しくOCRする入口を追加。保存された手動調整済み行座標は使わない。実ファイルのSHA-256、画像寸法、初期矩形、設定付き検出器改訂、抽出理由を記録する。
- 生成する候補は未承認。元画像上に独立して存在し、一意に包含する領域があるときだけ所属を付ける。既存領域・候補・原文・訳文・消去範囲は変更しない。比較特徴は保存JSONに混ぜない。
- 重なるOCR範囲を結合し、範囲数・総画素数・行／単語数・抽出件数を制限する。上限到達と対象外の領域を空の成功結果と区別する。単語座標が得られない本文は安全な抽出ができないため失敗として返す。
- 一括収集は開始時のカード・設定のコピーを逐次処理し、完了済み提案だけを通知する。個別失敗後も他カードを処理し、読込／抽出中の対象変更と中止では遅延結果・遅延エラーを捨てる。完了済み提案の類似グループ案を返すが、保存・自動置換は行わない。

## P1b / P2: 個別レビューとグループ整理の操作

確認UIへ接続する前の処理として、`review-operations.ts`へ次を追加した。

- 手動追加は現在の元画像ハッシュを要求し、保存と同じ座標・参照・件数上限で検証する。一意に包含する領域がある場合だけ所属させ、未承認で作る。
- 範囲・登録先の変更で承認を解除する。同じ値への操作では承認を維持する。初期検出枠は残し、範囲修正で所属先をはみ出したら所属だけを解除する。
- 除外・未確認への復帰は候補と所属グループを消さない。個別承認には現在の元画像・登録先画像の内容確認を要求する。所属先は承認と独立して明示確認できるが、存在しない領域や完全包含しない領域への指定は拒否する。
- グループ間の移動・統合・新グループへの分割・未分類化、代表・名前・登録先提案の変更。代表が移動したグループは残るメンバーから代表を選び、空グループを整理する。重複所属を防ぎ、個別の登録先・採用／除外判断・承認は変えない。
- 入力を独立コピーしてから検証・更新し、不正な操作の途中結果を保存しない。元のプロジェクトや候補、共有する座標オブジェクトを変更しない。
