# 無償翻訳の初期検証（2026-09-17）

関連: [Issue #5](https://github.com/happylifetaka/happy-locale/issues/5) / [改善案](../proposals/free-translation.md)

## 結論

Chrome Translator APIによる英日翻訳は実機で動いた。APIキーや有料APIの契約情報を設定せず、初回モデル取得と16回の翻訳を完了した。

一方、アセットタグをそのまま渡す方式は5文中2文でタグが壊れた。英数字の識別子へ退避する試作でも5文中1文で小文字化が起き、完全一致の復元に失敗した。タグの保持だけでは意味の正しさを保証できない例もある。本体への採用は未決定とし、次にタグ復元・不整合検出を実装して評価する。

これは少数のサンプル文での初回実測であり、一般的な精度や性能の保証ではない。本体の翻訳設定・既存プロジェクト・公開版の外部Endpoint制限は変更していない。

## 環境と方法

| 項目 | 実測内容 |
| --- | --- |
| OS | macOS 26.6.1 |
| ブラウザ | インストール済みGoogle Chrome 152.0.7977.84 |
| 実行方法 | Playwrightで画面ありのChromeを起動。専用の一時プロファイルを使用 |
| ページ | 127.0.0.1のローカルHTTP。secure context判定はtrue |
| API | `Translator` あり。en→jaの初期availabilityは `downloadable` |
| 初期化 | モデル取得を含め約4.28秒。進捗0〜1を観測 |
| 翻訳 | 11種類の文、タグあり5文は2方式で比較。合計16回、各4〜18ms |

実験フラグでAPIを強制有効化していない。Playwrightの標準起動引数にはコンポーネント更新等を無効化するものがあるため、この検証では標準引数を使わず、専用プロファイルとデバッグ接続を明示した。

初期化はページ上のボタンをクリックして開始した。既存の利用者プロファイルやプロジェクト画像は読み込んでいない。入力は同梱サンプルの英文と検証用に作成した短文だけを使った。

## 実際の出力と評価

以下の評価は実出力を読んだ開発時の一次所見。利用者によるゲームの意味・用語のレビューは未完了。

| 原文・方式 | 出力 | 所見 |
| --- | --- | --- |
| `Draw 2 cards, then keep 1.` | カードを2枚引いてから1枚残します。 | 数量と順序は保持 |
| `Do not discard this card.` | このカードを破棄しないでください。 | 否定は保持。用語の統一は必要 |
| `Move up to 3 spaces.` | 最大 3 つのスペースに移動します。 | 上限は保持するが「最大3マス移動」の方が自然 |
| `Spend 2 [icon:drop] to move up to 3 spaces.` を直接翻訳 | [アイコン:ドロップ] を 2 つ使用して、最大 3 つのスペースに移動します。 | タグの構文・名前が日本語化し、描画用タグとして使えない |
| 同じ文のタグを `ZXQICON1QXZ` に退避 | 2 zxqicon1qxz を使用して、最大 3 つのスペースに移動します。 | 識別子が小文字化。完全一致による復元は失敗 |
| `Spend 1 [icon:drop] to gain 2 [icon:sun].` を直接翻訳 | 1 [icon:drop] を 2 獲得する [icon:sun]。 | タグは両方残るが、消費と獲得の関係が不明瞭 |
| 同じ文を識別子へ退避して復元 | 1 [icon:drop] を 2 [icon:sun] にするために使用します。 | 直接翻訳より読みやすいが、用語・表現の確認は必要 |
| `Gain 1 [icon:太陽].` を直接翻訳 | ゲイン 1 [アイコン:大体]。 | タグの名前まで変わる |
| 同じ文を識別子へ退避して復元 | 1 [icon:太陽] を獲得します。 | 今回は復元できた |

全入力・出力・所要時間は[実測JSON](free-translation-2026-09-17.json)に保存した。JSONの `semanticReview: pending` は、人による最終確認を自動合格にしていないことを表す。

## 次に実装する内容

### 追加検証: 小文字の一時識別子

利用者の提案を受け、識別子を最初から `zxqicon1qxz` のような小文字にして同じ文を再翻訳した。今度は5文中4文で大文字化され、完全一致での復元に失敗した。大文字・小文字のどちらかに固定するだけでは解決しない。[追加実測JSON](free-translation-lowercase-2026-09-17.json)

両実測の退避方式の出力10件に対し、大文字・小文字を区別せず、各識別子がちょうど1回存在することを確認してから復元する処理を再適用したところ、10件とも元のタグの種類と数を復元できた。これは保存済み実出力に対する復元検証で、語順や意味の合格判定ではない。

したがって「翻訳されない文字列」を探すだけでなく、「変化を限定的に許容して復元し、復元不能なら候補を止める」方式を採用候補とする。任意のユーザー入力と識別子の衝突、未知の識別子、欠落・重複への対応は本体実装で追加する。

なお追加検証の最初の試行では、availabilityが `downloadable` でも `create()` が `NotSupportedError` になった。新しい独立プロファイルでの再試行は成功した。原因は未特定で、利用可否確認だけで初期化成功を保証できないことも確認した。

現行の検証スクリプトは小文字の識別子と完全一致復元を使い、この失敗を再現する。本体用の復元処理はまだ接続していない。

1. 原文と衝突しない識別子を生成し、アイコンの出現ごとに元のタグへ対応付ける。
2. 今回観測した大文字・小文字の変化を考慮して復元する。欠落・重複・未知の識別子は拒否し、曖昧な推測復元はしない。
3. 復元後のタグの種類・数を検証する。保持成功を翻訳品質の合格とは扱わず、必ず候補プレビューで確認する。
4. 数字・用語の確認を既存画面へつなぐ。特に消費・獲得、任意・強制、否定、移動元・移動先を評価する。
5. 非対応、モデル取得失敗、再試行、カード変更時の候補破棄を確認した後、一領域のProviderを本体へ接続する。

既存プロバイダーをブラウザ内翻訳で置き換えたり、翻訳結果を自動確定したりする段階には進めていない。

## 利用条件と未確認事項

- 公式資料ではTranslator APIはデスクトップChromeの端末内翻訳で、英語・日本語を対象にできる。実行時には言語ペアの利用可否確認が必要。モデルはChromeが取得・管理する。[Translator API](https://developer.chrome.com/docs/ai/translator-api)
- Translatorは専用モデルを使う。Gemini Nano向けの22GB空き容量などの要件を、この翻訳APIの必須条件としてそのまま記載しない。[導入要件](https://developer.chrome.com/docs/ai/get-started)
- Chrome実行形式にはGoogleの利用規約とChrome追加規約が適用される。ドキュメントのApache 2.0表記をモデルの再配布許諾とは扱わない。[Chrome追加規約](https://www.google.com/chrome/terms/)
- 今回はアプリにモデルを同梱せず、ChromeのAPIだけを呼んだ。認証キー・課金設定なしでの実行は確認したが、将来の料金保証やあらゆる用途の法的適合性を確認したものではない。

未確認:

- モデルの正確な識別子、容量、更新時の品質差、必要な追加表示や用途上の条件。
- 取得済み状態での再起動と、ネットワークを切断した状態での実行。
- 非対応端末・管理ポリシー・取得失敗時の実機挙動。
- 公開サイトの実オリジンでの動作、一括処理、取消、同時編集との統合。
- 利用者の実カード群での品質と、手直しを含めた所要時間。

## 再現手順

開発依存関係とGoogle Chromeをインストールした環境で実行する。

```bash
mise exec -- node scripts/probe-browser-translation.mjs /tmp/happy-locale-translation-probe.json
```

ループバックの検証ページと独立Chromeを開き、ボタン操作からモデル取得・翻訳を実行する。待機上限は翻訳処理全体で120秒。エラーと途中のイベントも出力JSONに記録する。通常のChromeプロファイルは指定しない。

専用プロファイルは一時ディレクトリ内に残り、場所を出力JSONの `profile` に記録する。公開する結果からは個人環境のパスを削除する。初回状態の比較用に毎回新しいプロファイルを作るため、モデルが再取得される場合がある。

実施済み確認: 実モデルによる16回の翻訳、追加スクリプトのESLint、差分の空白検査。本体機能は変更していないため全体の回帰テストは実行していない。
