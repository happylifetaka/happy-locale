# カード作業フローの改善・検証

実施日: 2026-09-22

対象: [想定フロー](../proposals/card-to-print-workflow.md)の改善案、およびレビューで挙げた再反映・単一カード・初回翻訳設定・追加カードの再開。

## 要件と確認先

| 要件 | 実装・確認 |
| --- | --- |
| アセット検出から一括反映へ進む | 「次へ」から対象カード選択へ接続。`card-workflow.spec.ts`で画面遷移・実OCR・保存結果を確認 |
| 追加カードだけを処理する | `RegionApplyDialog`の対象選択、`useQuickRegionApply.start(ids)`。未選択カードの保存データが変わらないことを確認 |
| 候補を追加済みの1枚にも再反映する | カード一覧の「このカードに反映」。1枚だけの合成プロジェクトで警告・修正・再実行を確認 |
| 手直しした原文を保護する | `lastOcrText`と現在原文を比較。手修正・空にした原文・履歴なしを単体テストで保護し、実ブラウザでは保存・再読込後も保護することを確認 |
| 必要なときだけ原文を置換する | 要確認から該当領域の個別プレビューへ進み、変更前後を確認して明示反映。既存訳保持・Undo/Redoは既存の反映テストを継続 |
| 警告から該当箇所へ戻る | 領域ID・出現候補IDを持つ一時的な問題情報を使用。該当領域の原文欄、該当アイコンとグループの選択状態をブラウザで確認 |
| プロジェクト切替・中止後に古い結果を使わない | 既存の反映処理の再検証に加え、導線側でもプロジェクト世代を確認。対象選択・フォーカスは世代変更時に破棄 |
| 初回翻訳設定をプロジェクト間で共有する | 前回の実装を維持。今回も`translation-setup.spec.ts`を回帰実行。詳細は[初回設定の検証](initial-translation-setup.md) |
| 説明を短く、詳細は補助導線にする | 主な案内を短縮し、保持条件・個別プレビューを詳細へ配置。対象選択・要確認・アイコン修正のスクリーンショットを目視確認 |

## 保存と互換性

- `TextRegion.lastOcrText`だけを任意のJSON文字列として追加。プロジェクトはversion 4のまま。旧データには履歴を推測して設定しない。
- OCR候補採用・アイコン反映と同じUndo単位で履歴用原文も保存・復元する。
- 訳文・書式は維持する。原文が変わった確認済み訳は下書きへ戻す。
- 比較・対象選択・警告の画面状態、画像などのブラウザ資源は保存しない。
- 元画像を変更せず、画像・プロジェクトの外部送信も追加しない。

## 初回実装の検証範囲（1ea78f0まで）

- 全160ファイル・1,538件の単体／コンポーネントテスト成功。
- ブラウザ13件成功。
- アプリ・テストの型検査、変更ファイルのESLint、`git diff --check`成功。
- 対象外カードの要確認保持と、再処理したカードだけの結果更新も単体テストで確認。

単体・コンポーネントテスト、アプリ・テストの型検査、変更ファイルのESLintと差分検査を実施。ブラウザでは合成画像・隔離したOPFSプロジェクトを使用する。対象は`card-workflow`、`quick-region-apply`、`icon-region-analysis`、`translation-setup`、`translation-review`の各spec。

利用者の37枚の画像や実プロジェクトは変更していない。今回のブラウザ確認は開発サーバーでの動作であり、公開用静的ビルド・公開反映・実プリンターでの印刷・Chrome実モデルの翻訳品質は今回の検証に含めない。

## 追加改善：反映内容と未反映理由の明確化

利用者から「何を反映するか」「要確認29枚で何を確認すべきか分からない」との指摘を受けて改善。

- 実行前に領域追加・アイコンタグ付き原文への更新・保持条件を明示。保存済みデータから算出した処理予定、カード別サムネイルと割当済みアイコン名を表示。照合前の数を成功件数として扱わない。
- 狭いカード一覧には「原文保護で保留」「検出・対応付けの問題」の枚数と結果を開くボタンだけを表示。詳細は`RegionApplyResultsDialog`へ分離。
- 保留時は原文だけでなくアイコン・枠も未更新であること、現状を使うなら操作不要であることを明示。編集済みとOCR履歴なしの理由を区別し、保護条件は維持。
- サムネイル・カード番号・領域名・現在の原文とともに、比較・領域編集・アイコン候補編集への導線を表示。対応付けの具体的な問題と同じ領域の汎用エラーは二重表示せず、別原因のOCRエラーは残す。
- 合成37枚・保留29枚のブラウザ検証を追加。予定件数・分類・横方向のはみ出し・29枚目の編集への移動を確認。スクリーンショットでも対象選択と結果画面のレイアウトを目視確認。

追加改善後の実行結果：全162ファイル・1,546件の単体／コンポーネントテスト、ブラウザ10件、アプリ・テストの型検査、変更ファイルのESLint、`git diff --check`に成功。ブラウザは`card-workflow`・`quick-region-apply`・`icon-region-analysis`の3specを対象とする。利用者の実画像37枚は使わず、隔離した合成プロジェクトで検証している。
