# ブラウザ内翻訳の実装と検証

日付: 2026-09-17

追跡: [Issue #5](https://github.com/happylifetaka/happy-locale/issues/5)

設計: [無償翻訳による下訳の一括生成](../proposals/free-translation.md)

## 実装した動作

- 翻訳設定に「ブラウザ内翻訳（英語 → 日本語・試験機能）」と対応状況の確認を追加した。
- 一領域の翻訳と、一括確認からの未翻訳候補取得に接続した。公開用ビルドの外部Endpointは引き続き無効。
- 初回モデル取得の進捗、処理の中止、失敗行だけの再試行に対応した。
- 既存の手修正済み訳を一括取得で上書きしない。候補を適用するまでプロジェクトは変更しない。
- 一意に決まる同一原文の既存訳・用語集の訳を優先し、同じ一括処理内の同一原文は再翻訳しない。
- 原文・訳文・カードが変わった場合は、古い個別候補を破棄する。一括適用は既存の変更検出経路を利用する。
- 一領域の候補プレビューにも数字の差分を表示する。一括確認の既存の数字・タグ検査も利用する。
- デモは引き続き固定の同梱訳を使う。

## タグ保護

`[icon:名前]` は出現ごとの識別子へ退避する。通常は `zxqicon1qxz` などを使い、原文中に同じ接頭辞がある場合は別の接頭辞を選ぶ。大小文字の変化とタグの語順変更は許すが、各識別子が1回ずつ存在することを要求する。

欠落、重複、未知の識別子、壊れた元タグ、翻訳が新たに生成したタグはエラーにする。アセット名の `$` も置換式として解釈しない。文章をアイコンの前後で分断して翻訳しないため、文全体の文脈を入力できる。

タグ保持は意味の正しさを保証しない。今回の実モデルでも「消費して獲得する」が不自然な日本語になる例があり、試験機能として候補の確認を必須にした。

## 実モデル・画面での証拠

環境はmacOS 26.6.1、Google Chrome 152.0.7977.84。通常の利用者プロファイルとプロジェクトは変更せず、専用プロファイルとOPFS内の検証用カードを使った。

| 確認項目 | 結果 |
| --- | --- |
| 公開用ビルドの設定画面 | ブラウザ内翻訳の選択・対応状況確認・保存を実操作。外部Endpointの選択肢は非表示 |
| 本体Providerを実Chromeモデルで実行 | 通常文6種とアイコン付き5種の全11入力で出力を取得。アイコン付き5種すべてでタグを復元 |
| 公開用ビルドの一括取得UI | 原文2行を翻訳し、手修正済み1行を保持 |

| 取得済みモデル | availabilityが `available` |

## 再現手順

依存関係とGoogle Chromeが必要。検証スクリプトはモデルのダウンロードを伴う場合がある。

```bash
# 本体Providerと試作を実モデルで比較する
mise exec -- node scripts/probe-browser-translation.mjs

# 公開版をローカル生成し、本物の翻訳APIで画面を検証する（配置・pushはしない）
NUXT_PUBLIC_TRANSLATION_ENDPOINT_ENABLED=false mise exec -- node node_modules/nuxt/bin/nuxt.mjs generate
mise exec -- node scripts/verify-static-output.mjs
mise exec -- node scripts/probe-browser-translation-ui.mjs
```

画面検証ではフォルダ選択だけをテスト用OPFSフォルダに差し替える。翻訳API、タグ復元、候補適用、Undoは本体と実モデルを使う。画像・英文は同梱素材と検証文だけを利用する。

## 配布と利用条件

採用形態はChromeの標準APIの呼び出しであり、翻訳モデルやChrome自体をアプリへ同梱・再配布しない。追加の翻訳ライブラリ依存も増やしていない。初回取得・更新はChromeが管理する。

APIキーや課金情報なしで動作することを実測した。端末・通信・保存領域の負担は利用者側にある。Chromeには[Googleの利用規約とChrome追加規約](https://www.google.com/chrome/terms/)が適用される。MITのアプリライセンスがChromeやモデルに適用されるという意味ではない。

仕様確認元は[Chrome Translator API](https://developer.chrome.com/docs/ai/translator-api)と[Translator API仕様](https://webmachinelearning.github.io/translation-api/)（2026-09-17確認）。原文を端末内で処理する説明、対応状況の確認、初回ダウンロードの説明をUI・README・利用ガイドへ反映した。

## 検証の限界と後続評価

- 実モデルの品質評価は短文中心で、利用者の実カード群による修正時間の評価はまだ行っていない。
- 特定の翻訳モデルのバージョンを固定できない。Chrome更新後に品質が変わる可能性があるため、検証スクリプトで再測定する。
- モデルの正確な容量・内部識別子や、全管理ポリシー・全端末での挙動は保証しない。実行時の対応確認とエラー表示を設けている。
- 用語集は同一原文の訳の再利用に対応する。文中の用語をモデルへ強制指定する機能は追加していない。
- Argos Translateは今回導入していない。Chrome非対応環境は手動入力・CSVを利用する。
- push・公開サイトへの配置は行っていない。実オリジンへの配置後の検証は、公開する段階で行う。
