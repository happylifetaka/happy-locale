# OCR領域候補の特殊な検出・補正条件一覧

確認日: 2026-09-20。現在の実装を読み取った棚卸しであり、将来の仕様案ではない。

対象はカードの「領域候補を出す」と一括領域検出。OCRエンジン内部の学習内容、原文の辞書補正、翻訳処理は対象外。
ゲーム名・カードID・特定の見出し語による分岐はないが、英字、大文字見出し、淡色の帯、暗い背景の明るい文字を想定した条件がある。特定ゲームでの調整値も共通の既定値として残っており、別ゲームでの精度を保証するものではない。

## 1. 設定の所在と処理順

| 区分 | 現状 |
| --- | --- |
| 内部設定に分離済み | 文字画素補正・淡色帯再OCRの有効化、色の閾値、帯の形状条件、再OCR回数・採用信頼度 |
| 候補生成の引数で変更可能 | 余白、候補の最低信頼度、最低英字数、記号比率、画像高に対する最低行高 |
| コード内に固定 | 英字・大文字の判定、装飾誤読パターン、行結合、黒文字の画素補正、アイコン保護、重なり調整など |
| 未実装 | ゲーム別設定ファイル、設定UI、インポート、プロジェクトへの設定保存 |

処理順は「全体OCR → 原画像から淡色帯を探索・局所OCR → 文字画素の補正準備 → 行ごとの装飾除去・枠補正 → 候補フィルター → 横結合 → 縦結合 → 余白追加・余白の重なり調整」。局所OCRで確定した見出しは、候補生成時に元の確定枠を優先し、明るい文字向け補正を重ねない。

単体・一括とも[共通検出サービス](../../app/services/ocr/detect-regions.ts)が同じ順序で実行する。参照: [内部設定](../../app/services/ocr/detection-settings.ts)、[補正パイプライン](../../app/services/ocr/region-image.ts)、[候補生成](../../app/services/ocr/candidates.ts)。

候補生成の内部配置は、[行補正と縮尺復元](../../app/services/ocr/candidates/normalize.ts)、[フィルター・初期選択](../../app/services/ocr/candidates/filter.ts)、[見出し補正](../../app/services/ocr/candidates/headings.ts)、[行結合](../../app/services/ocr/candidates/grouping.ts)、[枠・余白の調整](../../app/services/ocr/candidates/geometry.ts)に分離した。以下の判定順・条件値は変えていない。

以下で輝度は `0.299R + 0.587G + 0.114B`、彩度は `max(R,G,B) - min(R,G,B)` を指す。いずれもRGBの0〜255を使用し、HSVの彩度ではない。画素解析のpxと、最終候補の原画像座標のpxは区別する。

## 2. 全体OCRの前提・前処理

- 全体検出は英語モデル・`sparse-text`を使用。名前・種別・効果などの意味的な分類は行わない。
- 画像を拡大し、グレースケール化と輝度分布の下位2%・上位2%を基準にしたコントラスト拡張を行う。
- 全体検出の画像余白は0。局所見出しOCRの余白は8px。
- 共通の画像準備関数は拡大率を1〜4に制限する。除外範囲が渡された場合は周囲の輝度中央値で隠すが、全体領域候補の呼び出しでは除外範囲を渡していない。
- 原画像の補正解析は長辺1200px以下に縮小して行う。これはOCR画像そのもののサイズ制限とは別。

参照: [画像準備](../../app/services/ocr/image.ts)、[単体検出](../../app/composables/useRegionCandidates.ts)、[一括検出](../../app/composables/useBatchOCR.ts)。

## 3. 分離済みの画像補正設定と既定値

### 3.1 明るい文字・色付きアイコン

| 設定キー（`textPixels`） | 既定値 | 用途 |
| --- | --- | --- |
| `enabled` | true | 明るい文字の画素補正を使用 |
| `minimumLuminance` | 175 | 文字画素は輝度がこの値より大きい |
| `maximumSaturation` | 100 | 文字画素は彩度がこの値より小さい |
| `iconMinimumLuminance` | 65 | 色付きアイコン画素は輝度がこの値より大きい |
| `iconMinimumSaturation` | 95 | 色付きアイコン画素は彩度がこの値より大きい |

### 3.2 明るい帯の見出し

| 設定キー（`lightLabels`） | 既定値 | 用途 |
| --- | --- | --- |
| `enabled` | true | 帯探索・局所再OCRを使用 |
| `minimumLuminance` | 145 | 帯の画素の輝度がこの値より大きい |
| `maximumSaturation` | 90 | 帯の画素の彩度がこの値より小さい |
| `minimumWidthRatio` | 0.12 | 帯幅が解析画像幅の12%以上 |
| `minimumHeightRatio` | 0.012 | 帯高が解析画像高の1.2%以上 |
| `maximumHeightRatio` | 0.07 | 帯高が解析画像高の7%以下 |
| `minimumAspectRatio` / `maximumAspectRatio` | 3 / 22 | 帯の幅÷高さの許容範囲 |
| `minimumFillRatio` | 0.38 | 外接矩形内を帯画素が占める割合の下限 |
| `maximumRequests` | 10 | 1画像の局所OCR回数上限 |
| `minimumConfidence` | 50 | 局所OCRの採用語の平均信頼度の下限 |

設定は内部API用。外部JSONの仕様や入力検証は未実装。これらを無効化しても、候補生成側の装飾除去や行結合まで無効になるわけではない。

## 4. 明るい帯の探索・局所OCRに残る固定条件

- 上下左右4近傍の連結画素を使う。3画素未満の成分は捨てる。
- 帯を上から順に処理し、探索矩形には原画像座標で各辺2px相当の余白を付ける（画像端で制限）。
- 全体OCRに「信頼度65以上、英字8文字以上」の行が必要。その最上行より上に始まる帯は再OCRしない。該当行がなければ局所OCR自体を実行しない。
- 帯を黒文字の画素条件で絞ってから、英語モデル・`single-line`で読み直す。
- 採用語は英大文字のみ。各語は2文字以上、最終見出しの先頭語は3文字以上、最終見出し全体は1〜4語。
- 採用語以外に「英字を含み信頼度30超」の認識片があると見出し全体を不採用にする。
- 信頼度は採用語の単純平均。不明値はここでは0として計算する。
- 既存行の置換には「英字3文字以上」「大文字率60%以上、または新しい見出し文字列を含む」「行の縦中心が帯内」「横範囲が新見出しと重なる」を要求する。
- 置換対象の行と、その枠内に中心がある単語を除き、新しい見出しを追加する。本文を無条件に削除する処理ではない。

影響: 小文字の見出し、数字を含む見出し、5語以上の見出し、暗い帯、上部の見出しはこの追加検出では拾えないことがある。全体OCRで拾える可能性とは別。

参照: [recoverImageLabels](../../app/services/ocr/region-image.ts)。

## 5. 暗い背景の明るい文字を絞る固定条件

- 対象行は信頼度40以上かつ英字5文字以上。不明信頼度はこの補正では対象外。
- 文字の連結成分は高さ5px以上かつ解析画像高の9%以下、幅2px以上かつ高さの2.5倍以下、面積が高さの1.4倍以上。
- 元行に含まれる同一トークン・信頼度70以上・連続英字2文字以上の単語を行位置の根拠にする。単語の中心が元行の内側であることも必要。
- 文字成分の高さは、根拠単語の高さ中央値（なければ元行高）の0.25〜1.6倍。
- 縦中心の差が大きい方の成分高の40%以内なら同じ行の成分としてまとめる。
- 4成分以上ある行を対象に、成分面積と根拠単語の縦位置への近さで採用行を選ぶ。
- 絞った文字幅が元幅の50%未満、または文字高が元高の20%未満なら補正しない。
- `g`や`y`など下にはみ出す字形を回収する。候補成分は現在の行と縦に重なり、上へのはみ出しが行高の25%以内、下へのはみ出しが50%以内、横位置が左右1行高以内。
- 高信頼度単語の高さが文字行高の1.7倍以下、縦中心差が0.5行高以下なら、その単語の横幅は削らない。
- 最後に解析画像上で各辺2pxの余白を付け、OCR座標へ戻す。

影響: 黒文字・色文字・短い名前・低信頼度行では同じ補正が働かない。長辺1200pxへの縮小率によって、解析上の固定pxが原画像で占める大きさも変わる。

参照: [createTextPixelRefiner](../../app/services/ocr/pixel-regions.ts)。

## 6. 本文内のアイコン・句点を残す条件

- OCRが記号として読んだものも保護する。元行のトークンと一致し、英字部分が1文字以下の単語が対象。
- 大文字率80%以上の行では、`« » • · *`だけの単語をこの保護から除く。種別の区切り記号を大きなアイコンとして扱わないため。
- 保護する単語枠は幅÷高さ0.25以上、幅が文字行高の2.5倍以下、高さが0.3〜2.5倍。文字行と縦に重なり、横中心が文字列左端から右端＋2行高の間にあることを要求する。
- 句点などの小さい明色成分は、幅0.3行高以下・高さ0.35行高以下で、文字行の近傍なら横幅に含める。
- 色付き成分の追加保護は、認識文に数字または `+ * % @ { } |` がある場合のみ。
- 色付き成分は幅0.25〜2.5行高、高さ0.35〜2.5行高、面積0.12×行高²以上。文字行と縦に重なり、左右1行高以内にあることが必要。

影響: アイコンを意味的に認識しているわけではない。灰色のアイコンや、OCRで特定の数字・記号が出なかった行では、色による保護が働かない場合がある。

## 7. 明るい帯の黒文字を文字際へ絞る固定条件

### 7.1 中央の黒文字を測る方法

- 切り抜きは幅20px以上・高さ8px以上。
- 横中央25〜75%で文字高を測る。黒文字は輝度110未満・彩度60以下、明るい背景は輝度150以上。
- 1行の黒画素率12〜75%、明色画素率25%以上を要求。
- 高さが切り抜きの30%以上の文字帯がちょうど1つあり、その上端が55%以下・下端が45%以上であることを要求。
- 横方向は黒画素が `max(2px, 文字帯高×15%)` 以上、明色画素が文字帯高×20%以上の列を使用。列の間隔が文字帯高×65%以内なら結合。
- 横中央をまたぎ、切り抜き幅の25%以上ある文字群を採用。他に文字帯高×80%以上の幅の群があれば曖昧として補正しない。
- 採用枠に各辺1pxを付ける。

### 7.2 中央測定が失敗した場合の補助方法

- 輝度20パーセンタイルと80パーセンタイルを取り、明側140以上・明暗差60以上の場合に限る。
- 暗側＋明暗差×35%を二値化閾値にする。黒画素率10〜80%の連続行を探す。
- 切り抜き高の40%以上ある帯がちょうど1つで、縦中央をまたぎ、高さ90%以下の場合だけ上下を絞る。
- 横方向は輝度110未満・彩度60以下の黒画素を使用。列間隔0.6行高以内を結合する。
- 切り抜き幅の65%以上あり横中央を含む主群を採用。他に0.8行高以上の幅の群があれば横方向は変更しない。
- 各方向に1pxの余白を付ける。横測定が失敗しても、上下だけ補正する場合がある。

共通ガード: 切り抜きが幅10未満・高さ8未満・幅2048超・高さ256超、非有限値、Canvas非対応・読取失敗なら元枠を維持する。

影響: 見出しが帯の中央にあり、淡い背景に暗い低彩度の文字があるという前提が強い。

参照: [heading-bounds.ts](../../app/services/ocr/heading-bounds.ts)。

## 8. 装飾を誤読した単語の除去条件

### 8.1 単語と行の照合

- 単語の中心が行内、単語面積の65%以上が行と重なることを要求する。
- 信頼度20以下・英数字なし・高さが行高の15%以下・行の下側25%内に始まるものは、罫線として照合から外す。
- 2〜7個の単語があり、横順に連結した文字列が行テキストと一致したときだけ、以下の装飾パターンを試す。

### 8.2 個別の誤読パターン

- **大文字1語＋片側の記号**: 語は3文字以上・信頼度80以上、装飾は英数字以外・信頼度40以下。装飾幅が平均文字幅の1.5倍以上、縦横比0.6〜1.5、高さが語高の80%以上、間隔が装飾幅の−25%〜語高の70%なら語だけ残す。
- **両側の装飾**: 中央語はすべて大文字2文字以上・信頼度80以上。左は英数字以外、右は英字以外。両端とも信頼度65以下、幅が平均文字幅の1.5倍以上、縦横比0.6〜1.5、高さが中央高の80%以上。左右装飾幅の比が65%以上なら中央語だけ残す。
- **左装飾＋末尾に句点が混ざった複数語**: 左は記号のみ・信頼度20以下。本文は大文字2〜5語で最後だけ句点を許容し、各語信頼度30以上・うち2語以上が80以上・平均70以上。左装飾の縦横比0.6〜1.5、間隔が装飾幅の−25%〜本文高の50%なら左装飾と末尾句点を除く。
- **左装飾が先頭語に融合し、右装飾が数字等になった場合**: 先頭側3〜5語が大文字、先頭信頼度40以下、2語以上が80以上、平均60以上。末尾は英字なし・信頼度75以下、幅が平均文字幅の1.3倍以上、縦横比0.6〜1.5、高さが本文高の60%以上、間隔0〜本文高の70%。さらに画像測定で左端が平均文字幅の70%以上内側へ動き、高さが85%以下になる場合にだけ末尾を除く。

### 8.3 上記パターンに一致しない見出しの補正

- 連続する英大文字3文字以上がある行を対象に画像の裏付けを確認する。
- 行と単語が一致し、すべて大文字2文字以上・信頼度80以上なら、文字端を切らないため元枠を維持する。
- 小文字が混じる場合は、行と単語が一致し、大文字語以外の信頼度が20以下などの追加条件を要求する。
- 中央の大文字語が信頼度60以上、外側の装飾が20以下なら、中央語だけの枠を再測定できる。高さ85%以下・幅80%以上の測定結果だけ採用する。
- 再測定で幅が元の85%未満になった場合、枠内が大文字語のみ・枠外が信頼度65以下と確認できれば文字列と平均信頼度も更新する。外側に語が残り、その裏付けが取れないときは元枠へ戻す。

影響: 「記号や数字に見える装飾」を除く規則なので、見出しに本物の記号・数字が含まれる形式では要検証。単語を削除する条件は、単なる枠の縮小とは区別が必要。

参照: [trimHeadingDecorations / refineLabel](../../app/services/ocr/candidates.ts)。

## 9. 候補として残す条件・初期チェック

| 条件 | 現在の扱い |
| --- | --- |
| 空文字、幅または高さ2px未満 | 除外 |
| 信頼度0以下 | 結合前に除外 |
| 信頼度が指定最低値未満 | 除外。指定最低値の既定値は0 |
| 英字数 | 既定で3文字以上必要 |
| 空白を除いた文字列中の英数字以外の割合 | 既定で50%以下が必要 |
| 行高÷原画像高 | 既定で1%以上が必要 |
| 信頼度が0超〜40以下 | 他条件を満たせば未選択で残す |
| 信頼度40超、または不明 | 他条件を満たせば初期選択 |

影響: 数字だけ、2文字の語、日本語だけの領域は既定の英字数条件を通らない。信頼度は文字認識の値であり、枠の正しさの確率ではない。結合後の信頼度は不明値を除いた構成要素の単純平均。

## 10. 同一行・複数行を結合する条件

### 10.1 大文字ラベルの分類

- 英字3文字以上、英字の80%以上が大文字ならラベルとみなす。特定の見出し語や種別名の辞書照合はしない。
- この分類はカード名・種別・見出し・本文の意味分類ではない。大文字のカード名もラベル側になる。

### 10.2 横方向の結合

- 小さい方の高さを `h` とすると、高さ比40%以上・縦重なり70%以上・横間隔1.5h以下。
- 通常の重なり許容は0.2h。本文断片なら0.5h、右側が非英字で始まる本文断片なら `min(1.5h, 小さい幅×40%)` まで許容する。
- 本文断片とみなす条件は、双方が非ラベル、双方に英単語1語以上、少なくとも片方に3語以上、信頼度の高い方70以上・低い方25以上。
- 初期選択状態が違う行は原則結合しない。ただし本文断片が横に重なるか、右が非英字で始まる本文断片なら結合を許す。

### 10.3 縦方向の結合

- 初期選択状態が同じで、大文字ラベルかどうかも一致することが必要。
- 横重なりは小さい幅の20%以上。縦重なりは小さい行高の35%まで、通常の行間は小さい行高の80%まで。
- 左端差が小さい行高の50%以内、高さ比40%以上、両行の信頼度が70以上または不明の本文では、許容行間を `min(小さい行高×1.5, 大きい行高×1.1)` に広げる。
- 大文字ラベル同士は高さ比72%以上も要求する。
- 間に別グループの行があり、前後両方に横方向20%以上重なる場合、その行を飛び越えて結合しない。

影響: 複数行の種別を一つにする一方、近い位置・似た字高の別見出しも結合し得る。名前や種別を固有の役割として認識しているわけではない。

## 11. 最終枠の余白・上下の重なり

- 候補生成関数の既定余白は8pxだが、アプリの単体・一括呼び出しでは6pxを指定する。
- グループ内の全行が補正済み、または局所OCR確定見出しなら、候補余白は最大2pxにする。横結合で新しい行オブジェクトになった場合、この補正済み判定は引き継がれない。
- 枠の左上は切り捨て、右下は切り上げ、画像端を越えないよう制限する。
- 内容の枠は離れていて余白だけが上下に重なる場合、内容間の中央で余白を調整する。可能なら最大1pxの隙間を設ける。
- 内容の枠自体が重なる場合は、文字・アイコンの切断を避けるため、この重なり調整では動かさない。
- 「上下に分割」は意味解析ではなく、保持したOCR行数の中央で分割する。余白既定6pxで、元候補の枠内に制限する。

## 12. 安全策と未対応範囲

- Canvasが使えない、測定が曖昧、画素取得に失敗した場合は元OCR枠を維持する。
- 局所OCR失敗時は呼び出し側の診断処理へ通知し、全体OCR結果に戻る。カード切替・キャンセル後など古くなった結果は採用しない。
- 追加OCRは同じローカルProviderを使用する。ゲーム専用画像や設定の外部送信は追加していない。
- ゲーム判別、名前・種別・効果の意味認識、アイコンの意味認識、すべての誤検出の除去、すべての枠重なり解消を行う実装ではない。

## 13. 今後、専用設定へ分離する候補（未実装）

- 言語・英字数フィルター・大文字ラベル判定。
- 淡色帯の中央黒文字という前提と、その固定閾値。
- 装飾を記号・数字として誤読したときの除去パターン。
- 本文と種別の行結合条件、アイコン保護のトリガー。
- 初期選択信頼度、通常余白・補正後余白。

ゲーム専用プロファイルを公開リポジトリへ同梱することを決めたものではない。専用設定の保管・共有方式は別途検討する。
