# 領域検出の内部設定分離

## 実装範囲

`app/services/ocr/detection-settings.ts` に内部設定の入口を置く。明るい文字の画素補正と淡色帯の見出し再OCRに加え、候補生成と黒文字測定を組込ポリシー単位で選択できる。`detectRegions`へ呼出し単位で渡し、単体・一括検出は同じ既定値を使う。共有既定値は凍結し、部分設定は実行ごとに解決する。

| 設定 | 変更できる範囲 |
| --- | --- |
| `candidates` | 候補フィルター、初期チェックの信頼度、装飾除去、大文字ラベル分類、行内・複数行結合と間隔、補正後余白、余白の重なり調整 |
| `headingPixels` | 中央黒文字測定の有効化、文字と背景の色・明暗差の閾値 |
| `textPixels` | 明るい文字の画素補正、文字・色付きアイコンの閾値、色付き成分の保護トリガー |
| `lightLabels` | 淡色帯の探索と大文字見出し再OCR、色・形状条件、実行回数・採用信頼度 |

既定値と安全条件は[条件一覧](ocr-detection-conditions.md)を参照。装飾誤読の各パターン・単語照合の安全条件は`candidates/headings.ts`、結合の形状条件は`candidates/grouping.ts`、中央黒文字の形状条件は`heading-bounds.ts`に残す。局所OCRは英大文字1〜4語という組込ルールのままで、別言語の認識を提供する変更ではない。

これはゲーム別プロファイル機能の完成ではない。型は信頼された内部コード用であり、外部入力の型・範囲検証、画面上の切替、保存形式の変更は追加していない。任意コードを読むプラグインでもない。`headingPixels.policy: 'none'`は画素測定だけを止め、単語からの装飾除去は`candidates.headingDecorations: 'none'`で別に止める。`textPixels`・`lightLabels`も個別に無効化する。候補生成の従来の直接フィルター引数は維持し、新しい`settings`の値より優先する。

## 非公開プロファイルの今後の扱い（未実装）

- 公開リポジトリには共通エンジンと設定仕様だけを置き、特定ゲームの設定・画像・辞書を同梱しない。
- 専用設定は利用者が管理するローカルJSONとして読み込む方向を推奨。任意のJavaScriptを実行するプラグインにはしない。
- インポート時の型・範囲・バージョン検証は、外部入力を追加するときに実装する。現在の内部設定型をそのままファイル形式として固定しない。
- プロジェクトへの同梱は共有時に専用設定も渡るため、ローカル参照と同梱のどちらにするかは未決定。非公開設定が自動的に書き出される仕様にはしない。
- AIによる作成支援や外部送信は追加していない。
