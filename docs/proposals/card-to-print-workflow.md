# カード追加から印刷までの想定フロー

更新日: 2026-09-22

この文書は、利用者の基本フローと画面の役割を整理したものです。現状の実装に基づく操作と、今後整理したい導線を分けて記載します。実機での全工程の検証完了を示すものではありません。

## 基本方針

- 最初にアイコンの種類を整理し、領域・原文を一括作成して、気になる箇所だけ修正する。
- アイコンや領域を一つずつ承認する操作は基本フローに置かない。
- アセットは1グループに1つ関連付け、出現箇所ごとの登録・囲み直しを不要にする。
- 領域・アイコンは自動反映後に修正する。訳文は候補を確認してから反映する。
- 既存の編集を保持し、問題のある箇所から適切な修正画面へ戻れるようにする。

## 基本フロー

カード編集を始める → 翻訳設定（未設定時のみ）→ プロジェクト作成・画像追加 → アセット検出・整理 → 領域検出・アイコン反映 → 領域・原文の修正 → まとめて翻訳 → 仕上がり確認 → 印刷

### 初回のみ：翻訳方式を確認・保存する

「カード編集を始める」で通常のカード編集画面に入った際、保存済みの翻訳設定がなければ、既存の翻訳設定モーダルを自動表示します。「翻訳プロバイダー」の上に、未設定の間だけ次の案内を表示します。

> 初回のみ、翻訳方式を選んで保存してください。設定は他のプロジェクトでも共通で使います。

手動または利用する翻訳方式を選び、保存して進みます。ブラウザ内翻訳は対応状況を確認でき、初回の翻訳実行時に必要なモデルを取得します。非対応の場合は手動を選び、CSV・直接入力を利用できます。確認画面を開くだけでは、翻訳やモデル取得は開始しません。

設定はプロジェクトではなく同じブラウザ・同じサイトの `localStorage` に保存します。既存の有効な保存済み設定も引き継ぎ、プロジェクトの新規作成・切替ごとに確認を繰り返しません。変更するときは「ツール → 翻訳設定」を開きます。

キャンセルでは初回設定を完了扱いにせず、次回のカード編集開始時に再案内します。別ブラウザ・別端末や保存データの削除・破損時には再設定が必要です。ブラウザが保存を許可しない場合は現在の画面内で設定を利用できますが、次回まで保持できません。デモ開始時は初回案内を表示せず、通常用の設定を保存しません。

### 1. プロジェクトを作成し、カード画像を追加する

保存先フォルダを選び、カード画像をまとめて追加します。既存の作業ではプロジェクトフォルダを開いて再開します。

### 2. 「アセット検出」でアイコンを収集・整理する

対象カードからアイコン候補を収集し、似たものをグループにまとめます。利用者は次の内容を確認・修正します。

- 誤検出の除外
- グループ分けの修正
- 複数のアイコンを囲んだ候補の分割と枠調整
- グループ名の設定
- グループごとのアセット登録、または登録済みアセットへの関連付け

1グループに1アセットを設定すると、そのグループの出現候補全体に関連付けます。個々の出現箇所の承認は不要です。新規アセットは代表候補から登録するため、別画面で同じ位置を囲み直す必要はありません。

アイコン収集のためだけに、先に翻訳領域を確定する必要はありません。アイコンのないカードでは、この工程を省略できます。

この時点では、原文・訳文・カード上の描画は変更しません。

### 3. 領域検出・アイコン反映を一括実行する

現状は「カード」画面の「まとめて領域検出」で「追加・アイコン反映まで実行」を選びます。通常プロジェクトでは初期選択されています。一括処理はカードが2枚以上の場合に利用します。

- 領域も候補もないカードは、新しく領域と原文を検出する。
- 保存済みの領域候補がある場合は、選択済み候補を領域へ追加する。
- 既存領域は再利用し、作り直さない。
- 収集・関連付け済みのアイコンを現在の領域へ対応付け、OCR用の画像コピーでアイコンをマスクし、原文に `[icon:名前]` を挿入する。
- アイコンの小さなはみ出しは、安全に補正できる場合だけ領域を最小限拡張する。

アイコンごとの確認ダイアログは挟まず、反映後に修正します。対応が曖昧な箇所や処理に失敗した箇所は「要確認」にまとめます。

既存の訳文・書式は保持します。原文が変わった確認済みの訳は下書きに戻します。曖昧な対応やOCR失敗がある既存領域は変更しません。新規領域でアイコン処理だけに失敗した場合は、元の検出枠・原文で追加します。

未選択の候補や既存領域と重なる候補は保持します。反映はカードごとにUndoでき、中止時は完了したカードの結果を保持します。元画像ファイルは変更しません。

1枚ずつ進める場合は、領域候補の「アイコンも反映」を選んで「追加・アイコン反映」を使います。この選択肢は、そのカードに関連付け済みアイコン候補がある場合に表示します。

### 4. 各カードで領域・原文を修正する

反映結果を確認し、誤検出や不足を修正します。「要確認」だけでなく、警告にならない読み間違いや欠落も画像と照合します。

| 修正したい内容 | 修正先 |
| --- | --- |
| 文章の枠、区切り、領域の不足・重複、OCR誤読 | カード画面の各領域 |
| その領域だけのアイコン位置や不足 | 各領域のアイコン編集 |
| アイコンの種類、グループ分け、出現候補の誤検出 | アセット検出 |
| 登録したアイコン画像の切り抜き・背景など | アセット編集 |

「元画像のアイコンを指定」は手動追加・微調整用です。通常フローの必須工程にはしません。

候補の枠・分類・関連付けを変更した場合は、必要なカードで領域・アイコン反映を再実行します。アイコン候補は元画像上の座標で保持するため、領域を変更しても、その位置から現在の領域との対応を調べ直します。ただし、領域外や複数領域にまたがるなど、対応できない場合は修正が必要です。

### 5. 「まとめて翻訳」で訳文候補を確認・反映する

領域・原文・アイコンタグを整えてから、訳文候補を取得します。一覧で原画像・原文・訳文を照合し、修正して反映します。

- 数字・符号・アイコンの名前や個数に問題がないか確認する。
- 同じ原文の既存訳を利用できる場合は再利用する。
- 必要に応じてCSVや直接編集を利用する。

通常プロジェクトでの画面内の一括候補取得はブラウザ内翻訳に対応しています。Translation Endpointは別の個別送信確認フローです。利用する翻訳方式によって操作が異なります。

訳文候補の取得だけでは、既存の訳文を上書きしません。利用者が確認して反映します。

### 6. カード上の仕上がりを確認する

カードの編集結果を見ながら、改行・文字サイズ・配置・アイコン表示・背景処理を調整します。

原文中のアイコンをOCR用にマスクする処理と、印刷画像の背景補修は別です。元の文字やアイコンが意図せず残っていないか、訳文側のアイコンが正しく描画されているかも確認します。

現状、文字のはみ出しや印刷前チェックをすべて自動で集約する機能はありません。最終的な見た目は利用者が確認します。

### 7. 印刷範囲・実寸を確認し、PDFを出力する

1. カードごとに印刷範囲を設定する。同じ配置なら「未設定カードへ一括適用」を利用し、各カードで確認する。
2. 元画像のDPIを確認・設定する。
3. 「PDF(A4)作成」で列数・余白・間隔・トンボを調整する。
4. PDFを保存し、「実際のサイズ／100%」で印刷する。

初回は仕上がりの寸法を定規で確認します。印刷範囲やDPIが未設定の場合は、先に設定を完了します。

## 保存のタイミング

アセット整理後、領域・原文の修正後、訳文反映・仕上がり調整後を保存の目安にします。作業途中でも保存できます。

各処理の反映と、プロジェクトフォルダへの保存は別操作です。未確定の領域候補も保存できますが、未採用の再収集比較案やUndo履歴は保存されません。

## 画面の役割

| 画面 | 主な役割 | 基本フローでの位置付け |
| --- | --- | --- |
| カード | 領域・原文・訳文・背景・印刷範囲の編集 | 主な作業場所 |
| アセット検出 | アイコンの出現箇所を収集し、分類・登録・関連付け | アイコンを使う場合の準備工程 |
| アセット編集 | 登録済みアセット画像の調整 | 必要な場合だけ利用 |
| まとめて翻訳 | 訳文候補の取得・比較・修正・反映 | 原文を整えた後 |
| PDF(A4)作成 | 印刷用の配置確認とPDF出力 | 仕上がり確認後 |

## 現状の制約

- 領域・アイコン反映は、収集・関連付け済みのアイコン候補を利用する。アセットの登録だけで未知の出現箇所を探索する処理ではない。
- 既存領域があるカードは、その領域を再利用する。再実行だけで不足する文章領域まで自動的に作り直すわけではない。
- アイコン候補の再収集では比較案を作成し、選択した新規候補・枠変更だけを採用する。既存候補を無条件に上書きしない。
- 自動処理の成功や警告の有無は、検出結果・訳文・印刷画像の正しさを保証しない。

## 今後整理したい導線（未実装の改善案）

現状、アセット検出の「次へ：領域検出・アイコン反映」は、カード単位のプレビューモーダルを開きます。一括反映へ進むにはカード画面へ移る必要があり、基本フローと「次へ」の行き先が一致していません。

今後は次のように整理する想定です。

- 主導線は「アセット検出 → 一括で領域・アイコン反映 → カードで修正」にする。
- カード単位のプレビューは「反映前に個別確認」などの補助導線にする。
- アセット編集と手動アイコン指定は、必要な場合だけ使う補正機能として配置する。
- 「要確認」から対象カード・領域・アイコンと適切な修正操作へ迷わず移動できるようにする。
- 通常の説明文は短くし、詳細条件や注意事項は必要時に開く形にする。

利用者が毎回次の機能を選び直すのではなく、順番に進み、問題のある箇所だけ戻って修正できる導線を目指します。
