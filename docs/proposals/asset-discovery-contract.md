# アイコン候補と再検出の実装契約（P0）

2026-09-20。[全体計画](batch-asset-discovery.md)の実装時に守る境界を具体化したもの。保存・UIの実装完了を示す文書ではない。

2026-09-21追補（後述の当初契約に優先）: グループ割当は利用者の明示操作で全メンバーを統一し、候補移動では移動先の割当を継承する。登録先が変われば承認を解除する。登録後の「領域検出・アイコン反映」では、割当済み・非除外候補を作業コピー上で検証して原文案を作り、領域ごとの明示反映を確認とする。保存された個別承認は自動変更しない。既存枠は維持し、候補の元画像座標から一意に完全包含される現在の枠へ再対応付けする。枠外・複数領域との重なり・手動指定との衝突では適用を止める。新規分はこの画面で位置・原文を確認したうえで通常領域へ追加し、採用したOCR候補だけを消費する。位置・原文・新規領域・候補消費は同一Undoで戻す。これはカード単位の原文反映であり、後述の既存枠を再検出して比較する処理とは別の提供単位。

## 保存形式

- 候補保存の導入時に `FolderProjectDocument.version` を4へ進める。旧3への任意プロパティ追加だけでは、旧アプリによる読込・再保存で確認状態が黙って消えるため。旧0〜3は既存の移行を経て、アイコン候補なしの4へ移す。未知versionは拒否する。
- プロジェクト直下の `assetDiscovery` にカード別の候補集合とグループを置く。既存の `cards[].ocrCandidates` とは分離し、OCR候補の確定・破棄では消さない。機能未使用時は省略可能。
- 候補はUUIDで識別し、カードID、元画像のSHA-256、元画像座標の初期矩形・現在矩形、生成元（検出器改訂／手動）、任意の所属先、判断状態を保存する。座標自体を候補IDにしない。
- 候補には検出元の画像寸法も保存し、その寸法内で矩形を検証する。画像差替えで寸法が変わった場合も旧座標を勝手に縮小・切捨てせず、承認と所属を解除して再確認用に保持する。現在カードと寸法が異なる候補の承認・所属は保存時にも拒否する。同寸法の差替えは寸法だけでは検出できないため、画像の明示採用と内容ハッシュ照合で失効させる。
- 所属先は `candidate` / `region` の種別とIDを持つ。参照先が不明になった場合は参照を外し、所属確認待ちに戻す。カードの削除確定時はそのカードの候補とグループ内参照を除く。空グループは除き、代表だけが消えた場合は残る候補から代表を選び直す。
- グループは所属候補IDの唯一の所有者とし、候補側に所属グループIDを重複保存しない。一つの候補を複数グループへ所属させない。グループの登録先は提案であり、個別の確定アセットIDを直接変更しない。
- アセット画像の改訂はPNG内容のSHA-256で識別する。既存アセットは読み込んだ画像ファイルから算出する。ID・ファイル名が同じでも画像が変われば承認は失効する。描画用scale・名前だけの変更は画像改訂ではない。
- 未保存の登録画像は既存runtimeの保存待ちBlobが所有し、候補JSONには混ぜない。ハッシュ計算と読込は非同期の対象照合に含める。初回から全原画像を同時にデコードしない。
- 候補は1カード100件・プロジェクト合計2,000件までを初期上限とする。保存JSONの既存20 MiB制限も維持する。手動追加・読込にも同じ上限を適用し、上限到達を明示する。
- Store action、保存署名、保存開始スナップショット、初回保存・保存中編集の採用処理に新データを含める。アセット削除時は登録先と承認を解除し、候補自体は残す。
- 生のOCR行・単語は保存しない。出現候補、承認の根拠、必要な所属対応だけを保存する。指紋・切り抜きサムネイル・Canvas等はruntimeの派生資源とする。

## 実測OCR座標の取得と寿命（改善案4）

- 抽出へ渡す行・単語座標は、OCR直後の実測値を元画像座標へ変換したものとする。補正・手動調整済みの候補矩形や保存済み `lines` は探索範囲の手掛かりに留め、実測座標として代用しない。
- 実測値は解析中だけ保持する。保存・再開後に候補を表示・整理するだけなら再OCRしない。再抽出や原文再構成で必要になった場合だけ対象範囲を読み直し、追加処理を利用者に案内する。
- 元画像・対象領域・OCR設定の変更後に古い実測値を流用しない。取得後と適用直前に対象を照合し、キャンセルや変更後に届いた結果は破棄する。
- 原文再構成に必要な単語座標が取得できない場合は、自動適用を止めて手動確認へ戻す。文字列の検索置換や手動調整済みの座標による推測で代用しない。

## 承認と適用

- 判断状態は未確認／採用／除外。採用時は「元画像ハッシュ・矩形・アセットID・アセット画像ハッシュ」を承認スナップショットとして記録する。この一致と所属先の有効性を、適用直前に別々に検証する。
- 矩形・登録先・画像を変更した候補は未確認へ戻す。グループ移動・統合・分割だけでは個別の承認・登録先を変えない。除外した候補も再検出の比較対象に残す。
- 領域候補確定時に `addRegions` 相当の操作から生成IDを取得し、候補ID→領域IDを対応付ける。Undoで領域がなくなったら所属確認待ちとし、壊れた参照を保存しない。分割後は一意に完全包含される場合だけ所属先を提案し、曖昧なら確認を求める。
- 再OCRは領域の独立コピーと承認済みの出現情報で行う。既存Storeの `sourceIcons` を先に更新しない。OCR失敗・取消・古い結果の破棄では画像・原文・訳文を変えない。
- 適用時は `sourceIcons` と原文を単一の編集操作で更新し、Undo/Redoでも一緒に動かす。原文に依存する翻訳状態の処理は既存ルールに従う。共有アセット登録はこのUndoに含めない。
- 位置だけの適用は別の明示操作・履歴とし、元アイコンの消去範囲が変わることをプレビューする。既存指定と衝突する場合は無言で置換しない。

## 再検出の比較

- 比較の要否は実行回数ではなくカードの現在状態で決める。確定領域または未確定候補があれば、保存・再読込後や手動領域だけの場合も比較へ進む。どちらもないカードには新規候補を提示する。アセット登録は通常の領域再検出の前提条件にしない。
- 再検出は元画像を現在の検出設定で再解析してから比較する操作とする。保存済み矩形の再追加や、枠内の原文のみの再OCRとは区別する。同じ条件では結果が変わらない場合があり、実行回数による学習・精度向上を前提にしない。解析・比較だけではデータ・未保存判定・Undo履歴を変えない。
- 再検出開始時の原画像・既存候補・確定領域のスナップショットに対して差分を作る。対応は元画像上の位置を主とし、文字列は補助にする。自動対応は相互に一意な1対1のみ。1対多・多対1・曖昧な対応は確認待ちにする。
- 差分の種類は変更／新規／今回未検出／変更なし／対応要確認。未検出は削除命令ではない。新規追加も利用者の選択を必要とする。
- 確認画面で枠修正・新規候補追加・変更しない判断を分ける。対応要確認は自動選択・自動追加せず、対応が解決するまで一括適用に含めない。原文更新は別の再OCRプレビューで確認する。
- 枠のみ更新する際は領域ID・原文・訳文・翻訳状態を維持し、アイコン・保護矩形・マスク点を元画像上の位置が変わらないように再基準化する。領域外へ出るデータは切り捨てず、適用を止める。
- 適用対象の現在値が比較開始時と違う場合は差分を破棄し、再比較を案内する。再適用・再検出で同じ領域が増殖しないことを回帰条件にする。
- 同一カード内で選んだ確定領域の枠修正・未確定候補の枠修正・新規候補追加は、全件を検証してから一つの操作として反映する。一件でも不正・変更済みなら選択分を一切書き込まず、理由を示す。Undo/Redoでも領域・候補と関連座標を一緒に復元し、共有アセットのPNGと未選択のデータは変更しない。
- 新規分は未確定の領域候補として追加する。再検出の文字列は対応確認用とし、既存の枠だけを直す操作で原文へ採用しない。差分の取消では既存データを変更しない。
- 差分レビューは実行中の作業コピーとし、確認後の通常領域とアイコン候補を保存する。未適用の領域差分自体の永続化は初期版に含めず、画面終了前に案内する。アイコン候補のレビュー状態の永続化とは区別する。

## 計測と進行判断

- P1aは実装方式を選ぶ試作。合成画像で期待する枠、色違いの分離、連続アイコン、キャンセル・上限を自動検証する。私有画像は調整用と評価用を分け、結果・ラベルは `docs/local/` に限定する。
- 抽出候補がアイコンの一部だけを囲む場合は「検出成功」と「切り抜き成功」を分ける。出現箇所の回収率、不要候補率、枠の包含率、隣接文字の混入、グループの誤統合を別々に数える。
- 評価用画像を開く前に、数値ゲートと手動操作の数え方をローカルの評価記録へ固定する。初期試作の結果を見て決めた値を、事前登録済みの基準とは表現しない。
- P1aから保存・確認UIへの移行は利用者の代表出力確認を挟む。待機中も保存・参照・差分の純粋処理と合成テストの実装は進められるが、全体の完了扱いにはしない。
- P2で一括収集→整理→登録→保存・再開の操作量を利用者と確認し、P3の再解析を接続する。公開素材は合成データだけとし、私有画像での調整値・正解表を同梱しない。
