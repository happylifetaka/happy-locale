## 合意した改善案と進め方

レビューの改善案1〜4は、次の実装条件として採用する。これは仕様の合意であり、実装・実機確認の完了を意味しない。

| 改善案 | 採用する方針 | 詳細 |
| --- | --- | --- |
| 1. 承認・登録と適用の分離 | アセット登録や候補の承認だけでは画像・原文を変更しない。再OCRは作業コピーで行い、確認後に `sourceIcons` と原文を一緒に適用・Undoする。位置だけの適用は別操作にする | 第5・6節 |
| 2. 領域との対応を安全に維持 | アイコン候補はカードと元画像座標に紐づけて独立保存する。領域候補の確定時に新IDへ対応付け、分割・削除・Undoなどで所属が不明になっても候補自体は残す | 第5節 |
| 3. 承認の有効範囲を限定 | 各出現箇所の元画像・矩形・アセットID・アセット画像改訂に対して承認する。これらの変更では再確認を求め、グループ整理だけでは個別の承認を変えない | 第5節 |
| 4. 実測OCR座標と編集済み座標の区別 | 抽出には補正・手動調整前の実測行・単語座標を使う。生の座標は永続化せず、再開後に必要な解析だけ再OCRする。候補の表示・整理だけなら再OCRしない | 第4節 |

2回目以降の領域検出は、既存領域を読み直して**比較・修正案を出す操作**とする。自動上書きや同じ領域の追加ではない。例えば、既存の「効果文」の枠が広すぎる場合は、その領域に対する枠の修正案を提示し、利用者が選んだ変更だけを適用する。枠だけの修正では原文・訳文・翻訳状態を維持する。今回見つからなかった領域も残し、新規追加や曖昧な対応は確認を挟む（第6節）。

操作の境界は次のように分ける。領域の再検出だけを行う場合に、アセット登録や原文の再OCR適用まで必須にはしない。

| 操作 | 提示する結果 | 既存データへ反映するタイミング |
| --- | --- | --- |
| 既存領域・未確定候補がないカードの領域検出 | 新しい領域候補。オプトイン時は別にアイコン候補も収集する | 利用者が候補を選んで追加したとき |
| 既存領域・未確定候補があるカードの領域検出（再検出） | 既存領域・未確定候補との差分。登録済みアセットがあれば照合の手掛かりにする | 利用者が修正案・新規追加を選んで適用したとき |
| アセット登録・出現箇所の承認 | 再解析に利用できる素材と、出現箇所ごとの確認状態 | 登録・承認状態だけを更新し、領域枠・原文・描画にはまだ反映しない |
| 原文の再OCR | 承認済みアイコンを使った原文と画像への影響のプレビュー | 利用者の適用時に原文と `sourceIcons` をまとめて更新する |

実装は「小さな抽出試作で目視確認 → 候補の収集・整理・登録・保存 → 登録済みアセットを使った再解析と差分適用」の順に進める。まず整理・登録の手間が減るか確認し、その後にOCR改善へ接続する。各段階の完了条件・検証は第8・9節に従う。

### 合意事項の受入条件

以下は今後の完了判定に使う条件であり、検証済みの一覧ではない。

| 対象 | 確認する動作 |
| --- | --- |
| 改善案1 | 登録・承認だけでは元画像の描画と原文が変わらない。再OCRの取消でも変わらず、明示適用後は一度のUndoでアイコン指定と原文が戻る |
| 改善案2 | 領域候補の確定では所属IDが引き継がれる。領域の削除・分割・Undoで所属が不明になっても、アイコン候補と調整した矩形は残る |
| 改善案3 | 同じファイル名・寸法の元画像差替えや、同じアセットIDでの再切り抜きでも承認が失効する。グループの整理だけなら承認は維持される |
| 改善案4 | 手動で拡縮した領域候補の保存済み行座標を実測値として使わない。保存・再開後の閲覧だけではOCRせず、再抽出時に必要範囲を測り直す |

| 条件を変えずに再検出 | 同じ結果は「変更なし」として扱い、実行だけではデータ・未保存判定・Undo履歴を変えない。繰り返すだけで精度が上がるとは案内しない |
| 差分の適用・取消 | 同一カードで選んだ確定領域と未確定候補の変更をまとめて検証・適用し、一度のUndoで戻せる。適用できない変更が含まれる場合は一部だけ反映せず、対象と理由を表示する |

## 1. 目的と対象

複数カードの領域抽出時に、本文中・本文付近のアイコンも候補として集める。似た候補をまとめ、人が範囲・同一性・名前を確認してアセットへ登録できるようにする。その後の解析では登録済みアセットを照合材料に使い、アイコンを文字として誤認識することや、本文と一緒に囲み損ねることを減らす。

ここでいう「アセット」は、まず本文に埋め込む小さなアイコンを対象とする。カードのイラスト全体、見出しの装飾帯、背景素材の汎用自動切り抜きは初期対象外。

登録後の改善は画像照合と座標情報による補助であり、OCRモデルの再学習ではない。必ず精度が上がるとは扱わず、登録前後の比較で判断する。

## 3. 利用者の操作フロー

```text
一括領域抽出（アイコン候補の収集を明示的に有効化）
  → 本文付近の候補収集 → 類似グループの提案
  → 人が範囲・グループ・名前を確認 → アセット登録
  → 登録済みアセットを使って再解析
  → 変更候補を確認 → 選択した結果だけ適用
```

1. 最初はオプトインで「アイコン候補も集める」を選ぶ。既存の領域抽出だけの動作を残す。
2. 領域候補とアセット候補を別々に確認できるようにする。アセット確認を後回しにしても領域の確認を進められる。
3. グループ一覧に代表画像、出現件数、出現カード数、未確認件数を表示する。単発候補も捨てない。
4. グループを開くと各候補の切り抜きと周辺画像、元カードへの移動、座標調整を提供する。検出漏れは手動追加する。
5. 誤検出の除外、別グループへの移動、グループ統合・分割、代表候補の選び直しを可能にする。
6. 名前と透明化結果を確認し、新規登録または既存アセットへの関連付けを行う。似ているという理由だけでは全出現箇所を確定しない。
7. プロジェクト保存・再読込で、未確認・除外・調整済み・登録済みの状態を復元する。
8. 登録後は対象カードを選んで再解析する。候補だけのカードと、確定済み領域を持つカードの扱いを分ける。2回目以降は既存結果との比較を経て適用し、単純に追加して二重の領域を作らない（第6節）。

登録用の代表切り抜きと、各カード上の出現範囲は独立させる。同じアセットでも画像ごとの大きさ・位置は異なるため、代表の矩形を全カードへコピーしない。

## 4. 候補抽出とグループ化

### 探索範囲と抽出

- OCR行・単語と領域候補、または既存領域を探索の手掛かりにする。本文領域の内部と文字高に応じた近傍に限定し、カード全体のイラストを初期探索対象にしない。
- 特定ゲームの語句・固定座標・専用画像を共通コードへ埋め込まない。本文の役割を判断できない場合は、探索した範囲と限界を確認画面で説明できるようにする。
- 色・明暗・連結成分・大きさ・縦横比・文字との位置関係を組み合わせる。色成分だけで内部が欠けるアイコンは、周辺の輪郭も検討して切り抜き案を作る。
- OCRの低信頼度だけに依存しない。アイコンが高信頼度の文字として認識される場合も、画像側の候補を残す。
- 数字、句読点、装飾線、見出しの縁を巻き込まないか評価する。初期版で灰色・単色・輪郭のみのアイコンを十分に拾えない場合は制約として明示し、手動追加を残す。
- 重なる探索範囲から出た同じ候補を重複排除する一方、隣接した別アイコンは安易に結合しない。
- カードごとの候補数・探索画素数に上限を設ける。打ち切りは「検出なし」と区別して通知する。

### OCR座標の取得と寿命

- 初回はOCR直後の、手動調整や候補枠の補正を受けていない行・単語座標を抽出処理へ渡す。OCR拡大後の座標を元画像座標へ変換して扱う。
- 現行の検出サービスは最終候補と行数を返し、単語座標を保存しない。実測座標を実行中の抽出処理へ渡す接続を追加するが、初期版では生の行・単語座標を新たに永続化しない。
- 保存後の再開で候補の表示・手動整理をするだけなら再OCRは不要。候補の再抽出・再解析に実測座標が必要な場合は、対象範囲だけ再OCRし、追加処理が発生することを案内する。
- 現在の領域候補に保存される `lines` は枠の手動変更に伴って拡縮されるため、元画像上の実測座標として流用しない。既存領域・候補枠は探索範囲を決める手掛かりとしてのみ使う。
- 処理時間を測り、必要な場合だけ元画像の同一性・OCR設定・検出器改訂と紐づけたキャッシュを別途検討する。

### グループ化と照合

- 背景・透明余白・サイズを正規化し、形状・色・縦横比で比較する。既存の類似度計算は土台であり、閾値は評価前に決め打ちしない。
- 色だけ違うアイコンが意味上別物である場合を優先して保護する。色の違いを背景差として消さないか、正規化前の特徴も含めて検証する。
- AとB、BとCが似ているだけでAとCまでまとめる連鎖を避ける。代表との一致だけでなくグループ内のばらつきも制限する。
- 一致が曖昧なら別グループまたは未分類として残す。既存アセットへの一致は提案であり、自動確定ではない。
- 「OCR信頼度」「画像の類似度」「確認済み」を分けて表示する。類似度を正解確率とは呼ばない。
- 切り抜き範囲を修正したら特徴と照合結果を再計算するが、人が確定したグループを無断で組み替えない。

## 5. 保存・状態・履歴

以下は保存設計である。P0の[実装契約](asset-discovery-contract.md)に基づき、保存先・上限・version 4への移行とStore・保存処理の基盤、表示中の元画像・参照中アセットの内容照合を接続した。候補収集・確認画面からの一連の操作は未実装である。

| データ | 保存する内容 |
| --- | --- |
| カード別の出現候補 | 安定した候補ID、カードID、元画像座標の矩形、関連する領域／領域候補ID（任意）、抽出理由、未確認・採用・除外状態、所属の再確認状態 |
| 出現箇所ごとの承認 | 関連付けたアセットIDと、承認時の元画像の同一性・矩形・アセット画像改訂。グループの状態だけで承認済みと判定しない |
| グループ | グループID、所属候補ID、代表候補ID、仮の名前、整理状態、登録先アセットの提案（任意）。各出現箇所の登録先を暗黙に上書きしない |
| 調整情報 | 元の検出矩形と現在の矩形、手動追加・修正の区別、再検出時に保護する利用者の判断 |
| 解析条件 | 検出器・設定の改訂、元画像の同一性を検証する情報。別画像への差替えを寸法だけで判定しない |

- アイコン候補は「カードID＋元画像上の矩形」を基準として領域から独立して保持する。領域との関連は補助情報とし、領域候補の確定・破棄だけではアイコン候補を消さない。
- 現在は領域候補を確定すると別IDの通常領域が作られ、元候補が消えるため、確定操作で候補ID→確定領域IDの対応を取得・更新する。分割・破棄・削除・Undoで所属が曖昧になったら、アイコン候補を残して「所属の再確認待ち」にする。複数領域にまたがる候補を自動で割り当てない。
- 明示的な適用時に元画像座標から `sourceIcons` の領域内座標へ変換する。領域の移動・縮小・削除後にそのまま適用しない。アイコンとしての承認と、領域への所属の有効性は別々に検証する。
- 承認は出現箇所ごとの「元画像の同一性・矩形・アセットID・アセット画像改訂」の組に対して記録する。いずれかが変われば再確認へ戻し、古い承認を新しい解析へ流用しない。同じアセットIDでの再切り抜き・透過処理変更も画像改訂として扱う。
- グループの統合・分割・代表変更だけでは個別の承認を失わせない。ただし、それに伴う登録先の変更は各出現箇所へ提案し、改めて確認する。名前だけの変更は既存のトークン改名経路で扱い、画像改訂と区別する。
- PNGはアセット登録時に作る。全候補のPNGや指紋配列、Blob、Canvas、Object URL、ファイルハンドルは保存文書・Undoへ入れず、必要時に再生成する。
- 新規候補の保存に加え、読込検証・保存署名・保存開始スナップショット・カード削除・画像差替え・アセット削除の参照整合性を更新する。
- 候補保存の導入時に形式バージョンを4へ進め、旧0〜3の文書は候補なしとして移行する。旧アプリで新形式を保存して候補が黙って消えることを避ける。未知バージョン、不正座標、重複ID、壊れた参照、過大な件数を検証する。
- 再検出結果をいったん別案として持ち、調整済み候補・除外判断を無断で置換しない。破棄・置換は明示操作とする。
- 候補レビューの取り消しと、確定領域のUndo/Redoを区別する。矩形修正・統合・分割・除外にはレビュー内の取り消しを用意し、確定領域への反映は既存の編集操作を使う。セッション内のUndo履歴そのものは保存しない。
- アセット登録・候補の承認と、確定領域への適用は別操作。登録・承認だけでは `sourceIcons`・原文・訳文・画像の消去範囲を変更しない。原文のUndoで共有アセットを削除しない。
- 画像先行書込・文書保存・バックアップの既存契約を保ち、途中失敗でも存在しないPNGへの参照を保存しない。

## 6. 登録済みアセットによる再解析

再解析は後段の機能とし、一括収集・登録だけの段階で精度改善まで実装済みとは扱わない。

### 2回目以降の領域検出は比較・修正案として扱う

「再検出」と「既存領域への反映」を分ける。アセット登録の有無にかかわらず、既存結果があるカードでは新結果をそのまま追加・置換しない。登録後はそのアイコンも手掛かりにして本文の枠・アイコン位置を再評価する。以下は新たに実装する動作であり、現在の検出機能の説明ではない。

ここでいう「2回目以降」は実行回数を保存して判定するものではない。対象カードに確定領域または未確定候補があれば比較へ進み、どちらもなければ通常の新規候補を提示する。保存・再読込後や手動で領域を追加したカードでも同じ条件を使い、一括処理ではカードごとに判定する。

再検出では、対象カードの元画像を現在の検出設定で再解析し、新しい結果を既存領域・未確定候補と照合する。保存済みの枠をそのまま再追加する操作でも、既存の枠内の原文だけを読み直す操作でもない。登録済みアセットを使う場合も、照合による枠の提案と、承認済みアイコンを使った原文更新は分ける。

元画像・検出設定・利用するアセットが同じなら、結果が変わらない場合がある。再実行の回数による学習や精度向上は保証しない。アセットの追加・調整後は同じ画像の前後結果を比較し、改善したか利用者が判断して採用する。

| 再検出前の状態 | 結果の扱い |
| --- | --- |
| 確定領域も未確定候補もない | 新規候補を提示する。過去に検出していても、現在の比較対象がなければ同じ扱いにする |
| 未確定の領域候補がある | 前回候補と新しい候補を比較する。手動調整した枠・選択・除外判断を保持し、利用者が選んだ変更だけ採用する |
| 確定済み領域がある | 既存領域への修正案として表示する。対応する領域のIDを維持し、選択した枠の変更だけ適用する。原文・訳文・翻訳状態は保持する |
| 未確定候補と確定領域が共存する | 両方と照合し、既存の確定領域と同じ内容を新規領域として二重追加しない |

- 比較結果は「変更」「新規」「今回見つからなかったもの」と、変更なし・対応要確認を区別する。検出されなかった既存領域は自動削除しない。
- 同じカード・同じ元画像上の位置関係を主な手掛かりに、文字列も補助的に使って対応を提案する。矩形の重なりだけで同一領域と断定しない。1対多・多対1や曖昧な対応は利用者に確認し、安易な新規追加・統合・分割で解決しない。
- 適用前に変更前後の枠と対応先を表示する。新規領域の追加は明示的に選ぶ。枠の修正と原文の再OCRは別操作にし、枠を直すだけで認識文字列を上書きしない。
- 枠の変更では既存の `sourceIcons`・保護領域・手動マスクなど領域内座標を持つデータも検証する。単純な枠更新で位置をずらしたり、領域外の要素を黙って切り捨てたりしない。安全に変換できない場合は適用を止めて調整を求める。
- 比較開始時の画像・候補・領域の版を控え、レビュー中に対象が変わった場合は古い差分を適用しない。適用後の再実行でも同じ領域を増殖させず、Undo/Redoで枠と関連データを一緒に復元する。

例えば、既存の「見出し」と「効果文」が重なっている場合、2回目の検出ではそれぞれの枠の修正案を提示する。利用者が効果文だけを採用すれば、その領域のIDと原文・訳文を保って枠と関連座標だけを更新する。見出しの案は未適用のままにし、今回見つからなかった別の領域も残す。1つの既存領域を見出しと効果文の2つに分ける案は、単なる枠修正ではなく「対応要確認」として扱う。

確認画面では、まず「既存の枠を直す」「新しい未確定候補を追加する」「今回は変更しない」を選べるようにする。対応要確認の案は自動選択・自動追加せず、対応が解決するまで枠修正の一括適用へ混ぜない。原文も読み直したい場合は、枠修正とは別の再OCRプレビューへ進む。登録済みアセットがないことを理由に、通常の領域再検出を利用不可にはしない。

#### 差分の適用単位と失敗時の扱い

- 同一カード内で選んだ変更を一つの適用単位とする。確定領域の枠修正、未確定候補の枠修正、新規候補の追加が混在していても、書き込む前に全件の対応・座標・重複・比較開始時からの変更を検証する。
- 一件でも安全に適用できなければ、その選択分はすべて未適用のままにし、対象と理由を示す。利用者は選択を見直すか再比較する。成功した項目だけを黙って反映しない。
- 適用後は一度のUndo/Redoで選択分の領域・候補と関連座標をまとめて戻す／進める。共有アセットのPNGや、選んでいない領域・原文・訳文はこの操作で変更しない。混在適用の編集入口と、差分UIからの一連の操作の完了は区別する。
- 再検出で得た文字列は対応確認の材料として表示し、枠修正と同時に原文へ採用しない。新規分もまず未確定の領域候補として追加し、既存の候補確認・確定操作へ渡す。
- 差分画面を取り消した場合は既存データを変更しない。未適用の文字領域差分は初期版では保存しないため、画面終了時に案内する。保存できるアイコン候補のレビュー状態とは区別する。

### 領域候補を作る場合

登録画像と候補切り抜きを照合し、アイコンの位置を本文の境界判定へ渡す。本文中のアイコンを含めつつ、別の見出し・効果文まで巻き込まないことを検証する。最終枠からだけ探すと枠外の見落としを回収できないため、行・単語の近傍を使った探索を候補枠の確定前に接続する。

画像照合の候補だけで文字を消さない。有効な承認と明確な所属を持つ出現箇所に限定して、仮データでOCR除外と原文タグ生成へ進める。領域候補の確定時は第5節のID対応を更新するだけとし、別途利用者が適用するまでは `sourceIcons` を追加しない。

### 確定済み領域を読み直す場合

既存のOCR前処理・単語座標によるタグ生成は再利用するが、Storeへ `sourceIcons` を先に反映する手順はそのまま使わない。`sourceIcons` はOCR除外だけでなく、描画時に元アイコンを消すマスクにも使われるためである。

1. 対象領域の作業コピーへ、承認されたアイコン情報を一時的に重ねる。既存の手動指定と衝突する場合は確認を求め、全件置換しない。
2. 作業コピーを使ってアイコン範囲をOCR画像から除外し、単語座標から `[icon:名前]` を挿入して原文候補を生成する。
3. 原文候補と、アイコンの消去範囲を含む画像への影響をプレビューする。失敗・取消時は作業コピーだけを破棄し、確定領域・既存の消去範囲を変更しない。
4. 利用者が適用した時点で `sourceIcons` と原文を一つの編集操作として反映し、一度のUndoで両方を戻せるようにする。適用直前にも承認と対象の同一性を検証する。

「アイコン位置だけを適用」は再OCRの適用と別の明示操作にし、画像が変わることをプレビューで説明する。この操作は `sourceIcons` だけを更新し、独立してUndoできる。原文候補を取り消しても先に明示適用した位置は戻さない。単語座標が得られない場合は検索置換で代用せず、原文の自動再構成を停止して手動確認へ戻す。

既存の領域枠・原文・訳文・翻訳状態は自動で上書きしない。枠の再提案と原文の再OCRは区別して提示し、領域を差し替える場合の対応・履歴を確認する。原文変更後の翻訳状態は既存の編集ルールに従う。

確定済み領域のあるカードは現在の一括領域抽出の対象ではないため、専用の対象選択を追加する。既存バッチの対象条件を単に緩めて全領域を再生成しない。

## 7. 責務・非同期処理・非公開データ

- 抽出・特徴計算・グループ化はUI非依存のサービス／純粋関数へ、処理キューとレビュー操作は `features/cards/` 等の専用フローへ分離する。`CardEditor.vue` は接続に留める。
- 元画像は原則1枚ずつ読み、サムネイルは表示に必要な分だけ生成する。多数の原画像を常駐させない。全候補総当たり照合の負荷を測り、必要なら縦横比・サイズ等で比較対象を絞る。
- プロジェクト・カード・画像・領域・アセット改訂・要求世代を待機後に照合する。キャンセル、画像差替え、削除、画面破棄後の結果を反映しない。
- キャンセルは完了済みカードの候補を保持し、未完了カードの新結果を採用しない方針とする。既存OCRの中止動作との差をUIで明示し、即時Worker停止とは説明しない。
- 個別カードで失敗しても他カードの結果を保持する。部分成功と未処理・失敗を区別し、再試行で候補を重複させない。画像資源は成功・失敗・中断すべてで解放する。
- 画像・照合・グループ化は端末内で処理し、外部AIや画像サービスへ送信しない。生成AIによる設定作成は[別計画](ocr-detection-profiles.md)とする。
- アセット画像・ゲーム専用設定は利用者のプロジェクトに置く。公開コードへ同梱しない。私有画像の検証記録・出力はGit除外済みの `docs/local/` 配下に置き、公開テストは合成画像だけを使う。

### P3: 登録済みアセットを用いた再解析

確定領域の枠修正に加え、未確定候補の修正・新規候補追加を一度の通常Undoへまとめる`useCardEditor.applyRegionDetection`を追加した。Storeは全選択を検証して領域・候補・所属参照を一回で更新する。対象候補への後続編集があればUndo/Redoを止め、無関係な候補の編集は保持する。`useCandidateReview`で候補表示コピーを保存側の変更へ同期し、混在適用・通常Undo後の古い候補編集履歴を破棄する接続も追加した。差分UIからの呼出しは未実装。

`useRegionDetectionReview`で、実ファイルの同一性確認・非同期検出・差分の一時保持・明示適用をつなぐ制御も追加した。編集→Undo、画像・カード・設定の変更、取消・画面破棄後の古い結果を拒否する。保存済み／下書きの単体テストに加え、`detectFileRegions`で合成PNGを読み、実ローカルOCR→差分→実Store・表示コピー→通常Undoまでのブラウザ結合テストも追加した。通常の検出ボタン・差分UIにはまだ接続していない。

`source-ocr.ts`に、承認済みの出現箇所を作業コピーへ加え、原文候補と適用パッチを作る入口を追加した。手動指定の保持・重複排除・衝突拒否、単語座標からのタグ生成、位置だけ／原文と位置をまとめた適用の分離を検証した。合成PNGの実OCR→Store・共通描画→一度のUndo/Redo、取消・単語座標欠落時の保存内容・描画保持をブラウザで確認した。元画像とアセットの実ハッシュ取得を含む通常の操作制御、原文・画像プレビューUIへの接続は残っている。

実装状況: P0の安全条件に沿い、確定領域・未確定候補を混在させた比較と、選択した枠修正／新規候補追加を独立コピーへ適用する純粋処理を追加した。ID・既存文字列・翻訳状態の保持、関連座標の再基準化、二重追加と古い比較の拒否を合成テストで確認した。実検出から比較・編集入口・Store・混在Undoまでと、アイコンを使う原文再OCRの処理基盤は検証したが、通常画面からの呼出し、差分UIにはまだ接続していない。P2での利用者確認前に再解析フローを提供したものではない。

- [ ] 未確定・確定済み・混在カードの再検出比較、変更／新規／未検出の分類、曖昧な対応の確認、適用・Undoを実装する。

## 9. 検証と採用基準

自動テストは次を含める。

- 色・背景・サイズ違い、灰色アイコン、文字に似た図形、アイコンなし、連続アイコン、数字・句読点・装飾との隣接。
- 抽出の重複、範囲外座標、グループ化の連鎖、代表変更、色違いの誤統合、手動修正後の再計算。
- 保存・再読込・旧形式移行・未知形式拒否、削除や画像差替え後の参照、保存失敗・保存中編集。
- 登録・取消・再試行、処理中の対象変更、遅延結果破棄、カード切替、Undo/Redo、資源解放。
- 登録→出現箇所の確認→再OCR→原文候補の適用のブラウザE2E。単語座標が欠ける場合の安全な停止。
- 再OCR失敗・取消・遅延結果破棄で `sourceIcons` と描画・出力が変わらないこと。成功時の適用とUndoでアイコン指定・原文が一緒に変わり、位置だけの適用は独立して取り消せること。
- 領域候補を先に確定してからアイコンを確認する順序、候補分割・破棄・領域削除・Undo、複数領域にまたがる出現箇所の所属確認。
- 同一IDのアセット再切り抜きや候補矩形の変更で承認が失効し、グループ整理だけでは個別の承認・関連付けが書き換わらないこと。
- 保存後の再開時に、調整済み `lines` を実測値として使わず必要な範囲を再OCRすること。単に候補を表示・整理する際にはOCRしないこと。
- 2回以上の検出で領域が重複追加されず、未検出の既存領域も残ること。手動調整・除外判断の保持、曖昧な対応の確認、枠だけの適用で原文・訳文・翻訳状態が変わらないこと。
- 保存・再読込後、手動領域のみのカード、未確定候補のみのカードでも比較へ進み、既存結果のないカードだけが新規候補の提示になること。アセット未登録時にも通常の領域再検出を利用できること。
- 枠更新に伴うアイコン・保護領域・手動マスクの座標整合性、差分レビュー中の編集による古い適用の拒否、Undo/Redo後の再検出。
- 同一カードの確定領域と未確定候補をまとめた適用・一回のUndo/Redo。選択中の一件が不正・変更済みなら全件未反映となり、未選択のデータを保持すること。新規分は未確定候補に留まり、差分の取消では既存データを変更しないこと。
- Canvas確認枠が書き出し画像・印刷PDFへ混入しないこと。

実画像評価は候補件数だけでなく、見落とし・余分な候補・枠の不足／過大・誤統合／過分割・隣接文字の欠落・手動修正回数・確認時間・解析時間・メモリを記録する。OCR文字認識の改善と、領域境界の改善は別集計にする。

精度・時間の数値目標はP0で基準を測った後、調整前に固定する。最低条件は「確認なしの既存データ変更がない」「既存の成功例で文字欠落や誤結合が増えない」「評価用画像で手動作業量が減る」。平均改善で重大な失敗を隠さず、満たさない場合は探索範囲を狭めるか、手動確認中心の提供に留める。

## 10. 今回の初期版には含めないもの

- OCRモデルの学習・自動再学習、生成AIによる画像解析の外部送信。
- 任意コードを読み込むプラグイン機構、ゲーム専用素材の公開同梱。
- イラスト・背景・装飾帯を含む汎用オブジェクト抽出。
- 未確認候補の全自動登録、全カードの原文・訳文の自動上書き。
- 複数画像を合成して「正しいアイコン」を生成する処理。代表は実際の切り抜きから人が選ぶ。

複数の登録用見本、回転・強い変形への対応、別プロジェクトとの共有は、初期版の評価で必要性が確認できてから追加計画にする。
