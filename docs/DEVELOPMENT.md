# HappyLocale 開発引き継ぎ

最終更新: 2026-08-14

このファイルは、セッションが変わっても開発を継続できるように、現在の実装状況、設計判断、既知の課題、次の作業候補を記録するためのものです。

## プロジェクトの目的

手元のカード画像に含まれる英語テキストをローカルで除去し、日本語訳を重ねて PNG として保存する Nuxt アプリです。

重要な方針:

- 画像と生成物を外部サーバーへ送信・保存しない
- 画像検索、画像収集、翻訳済みカード共有機能を実装しない
- Canvas を中心にブラウザ内で処理する
- DeepL や OCR は差し替え可能なサービス境界を用意する

## 技術構成

- Nuxt 4.5.2
- Vue 3 / Composition API
- TypeScript
- Canvas API
- mise（Node.jsとpnpmのプロジェクト別バージョン管理）
- Node.js 24.15.0
- pnpm 11.21.0
- ESLint 10 / `@antfu/eslint-config` 9
- Vitest 3

Node.js 24.15.0とpnpm 11.21.0を `mise.toml` で固定しています。コード検査と整形は `@antfu/eslint-config` を基準とし、Prettier は使用しません。

## 背景処理の4モード

各 `TextRegion` は `backgroundMode` を持ちます。

### `auto`: 文字のみ自動補修

既定モードです。

1. 選択矩形の上・下・左・右の外側から背景色をサンプリングする
2. 周囲の多数派色から外れる辺と個々のサンプル画素（白文字、枠、アイコン等）の重みを下げ、4辺の色を内部へ補間する
3. 元画像と推定背景の色差・輝度差から文字候補マスクを作る
4. 元画像内の局所的な明暗差とRGB色差を確認し、滑らかな色面を除外しつつ孤立した色相差を検出する
5. マスクを膨張させて文字の縁や影を含める
6. 境界をフェザー処理し、マスク部分だけ推定背景へ置換する

明るい文字だけでなく、黒文字、灰色のアンチエイリアス、ドロップシャドウ用の暗部判定も実装済みです。

`autoMaskSensitivity` は 0〜100 で、既定値は 60 です。黒文字のシルエットが残る場合は上げ、背景まで消える場合は下げます。

`removeColorOutliers`（UIでは「色の外れ値を除去」）は既定で有効です。背景の多数派色と異なる赤・青・白などを局所RGB色差で補修対象にします。背景模様の色まで消える場合は領域ごとに無効化できます。

自動モードでは `backgroundColor` を使用しません。

### `manual`: 手動マスク補修

Canvas 上で赤いブラシを使い、補修する部分を直接指定します。

- ブラシサイズ変更に対応
- 複数ストロークを保存
- マスク消去に対応
- 赤いマスク表示は編集プレビューだけで、PNGには含まれない

ストローク座標は領域左上を原点としたローカル座標です。

### `solid`: 単色塗りつぶし

選択矩形全体を `backgroundColor` で塗ります。均一な背景や確実に消したい場合のフォールバックです。

### `none`: 塗りつぶさない（文字のみ）

元画像の画素を変更せず、矩形を日本語訳とインラインアセットのレイアウト領域としてだけ使用します。既存の見出し、空欄、ラベルなどへ文字を重ねる用途向けです。保護領域は背景には影響しませんが、テキストの折り返しと描画クリップには引き続き使用します。

## 保護領域

数字、アイコン、装飾などを残したまま、その周囲を一つの翻訳領域として扱うための子領域です。

- 座標は親の `TextRegion` 左上を原点とする
- 一つの翻訳領域に複数作成できる
- 背景の自動補修、手動補修、単色塗りつぶしの対象から除外する
- 日本語テキストは保護領域を避けて折り返す
- 黄色い編集枠は画面上だけに表示し、PNGには含めない
- ドラッグ選択後は追加モードを自動終了し、そのまま移動や四隅のハンドルでリサイズできる
- 追加、移動、リサイズ、削除は各操作につき一つのUndo履歴になる

定義: `app/types/editor.ts`

```ts

interface MaskStroke {
  brushSize: number
  points: { x: number, y: number }[]
}

interface ExclusionArea {
  id: string
  x: number
  y: number
  width: number
  height: number
}

interface TextRegion {
  id: string
  regionId: string
  displayName: string
  x: number
  y: number
  width: number
  height: number
  originalText: string
  translatedText: string
  backgroundMode: BackgroundMode
  autoMaskSensitivity: number
  removeColorOutliers: boolean
  backgroundColor: string
  manualMaskStrokes: MaskStroke[]
  exclusionAreas: ExclusionArea[]
  textColor: string
  textStrokeColor: string
  textStrokeWidth: number
  fontSize: number
  fontId: string | null
  textAlign: 'left' | 'center' | 'right'
}

interface FolderProjectDocument {
  version: 2
  name: string
  activeCardId: string
  cards: Array<CardProject & {
    id: string
    imagePath: string
    printArea: RegionDraft | null
    sourceDpi: { x: number, y: number } | null
  }>
  assets: ImageAsset[]
  fonts: FontReference[]
  printSettings: {
    columns: 1 | 2 | 3
    marginMm: number
    gapMm: number
    cutMarks: boolean
  }
}
```

読込前にversion別の移行処理を通します。version 0とversion省略形式はversion 1相当に補完し、version 1とともに`printArea`、`sourceDpi`、`printSettings`を補ってversion 2へ移行します。未知のversionは拒否します。

画像バイナリは状態や履歴に含めません。`HTMLImageElement` と Object URL にだけ保持し、履歴には `CardProject` のスナップショットを保存します。

`id` はアプリ内部の不変識別子、`regionId` はCSV照合用キー、`displayName` は領域一覧に表示する自由入力名です。日本語の名称は `displayName` に入れ、CSV照合や内部選択には使用しません。保存・読込時には主要コレクションの不正項目と重複ID、カード内の重複`regionId`、重複アセット名を拒否し、画面へ該当箇所を通知します。

Undo / Redoのスナップショットは直近100件に制限しています。ポインター移動中には履歴を作らず、領域の移動・リサイズが完了した時点で1件だけ保存します。

表示倍率は `CardEditor.vue` の一時的なUI状態です。Canvasの内部解像度、領域座標、手動マスク座標、PNG出力には影響させず、CSS上の表示幅と高さだけを変更します。

## 重要な設計判断

### OpenCV.jsはまだ導入していない

現在の自動補修は TypeScript と Canvas のみで実装されています。理由は、MVPの依存サイズを抑え、完全ローカルかつ導入しやすい状態を保つためです。

品質向上が必要になった場合の候補:

1. 現在の文字マスク検出をさらに調整
2. OpenCV.js の Telea 法によるインペイント
3. ONNX Runtime Web と LaMa 系モデルによるローカルAI補修

OpenCV.jsを採用する場合、配布ビルドに必要な `photo` APIが公開されているか確認し、なければWASMのカスタムビルドが必要です。

### 背景色指定は単色モード専用

自動補修で手動指定色を混ぜると全体の色調がずれやすいため、自動・手動マスクモードでは周辺画素だけを利用しています。「塗りつぶさない」モードでも背景色は使用しません。

### 背景処理は差し替え可能な純粋関数群

背景推定、マスク生成、合成は `app/utils/canvas/background.ts` に分離しています。将来OpenCV.jsやAI補修を追加してもUIへの影響を抑える方針です。

### プロジェクトはChromeのローカルフォルダへ保存

File System Access APIを使用し、ユーザーが選択したフォルダへ次の構成で保存します。

```text
project.json
project.backup.json
images/<card-id>.<ext>
assets/<asset-id>.png
```

- 最初に「プロジェクトを開く」でフォルダを選択し、`project.json`があれば既存プロジェクト、なければ新規プロジェクトとして扱う
- 新規プロジェクトでは中央の「カード画像を開く」で最初の画像を選び、初回保存時に同じフォルダの `images/` へコピーする
- 最初の画像はエディター状態から一時的な一覧項目とサムネイルを生成し、初回保存後に永続カードへ切り替える
- 2回目以降は同じフォルダの `project.json` を更新する
- 上書き前のJSONを `project.backup.json` に保存する
- プロジェクトJSONは将来の複数カード対応を見据えて `cards[]` を持つ
- カード一覧には全カードのメタデータを表示し、原寸画像は `activeCardId` の1枚だけを読み込む
- 開いたカードは最大144×180pxのJPEGサムネイルへ変換し、以後の一覧表示にはサムネイルを使う
- カード切り替え前に編集中の領域をメモリ上のプロジェクトへ戻し、次回の切り替えと保存で維持する
- 追加画像は1枚ずつデコードして寸法とサムネイルを取得し、原寸は `images/` へ保存後に解放する
- カード削除はカードをプロジェクト配列へ残したまま、対象IDを編集セッション内の削除予定として保持する
- 保存状態は、全カード・アセット・フォント・OCR辞書と書込／削除待ちIDを保存直後の署名と比較して判定する
- 削除予定カードは一覧の元の位置へグレー表示し、カードごとの操作メニューから個別に「削除を取り消す」を実行できる
- 保存時は削除予定カードを除外したプロジェクトJSONの書き込み成功後に、対応する元画像を削除する
- 画像はJSONやUndo履歴へ埋め込まず、表示対象だけを `File` とObject URLとして保持する
- カード編集の画像、Blob、FontFace、フォルダハンドルは `useProjectRuntime` に集約し、差し替え・削除・画面破棄時の解放も同Composableを経由する
- `project.json`相当の文書とアセット・フォント参照、OCR辞書、用語集はPiniaの `projectStore` が所有し、Blobなどのランタイム値をStoreへ入れない
- `useCardEditor` はカード別Undo履歴を維持し、編集・Undo・Redoの結果をカードID付きで `projectStore.updateCard` へ同期する。保存前の手動合流を状態同期の前提にしない
- JSON内の画像パスはプロジェクトフォルダ内の相対パスだけを許可する
- アセットは実行中に小さいCanvas/ImageBitmap、保存時に `assets/` のPNGとして保持する
- フォントファイルは保存せず、表示名・内部family・元ファイル名だけを保存する
- フォルダハンドルのIndexedDB保存と権限再取得は未実装

### 画像・プロジェクト読込の診断

ツールバー直下の「診断ログ」とChrome DevToolsのConsoleへ、`[HappyLocale]` 接頭辞付きで次の段階を記録します。

- 画像選択ボタン押下とfile inputのchangeイベント
- ファイルのMIME type、容量、拡張子（ファイル名と絶対パスは記録しない）
- Object URL作成、loadイベント、decode結果
- 画像寸法とエディターへの反映
- フォルダ権限、project.json、対象画像、領域データの取得

画像読み込みは `HTMLImageElement` のloadイベント成功を基準にし、`decode()`だけが失敗した場合はload済み画像を使用します。

### インラインコンテンツとフォント

描画処理は次の責務に分離しています。

```text
translatedText
  -> parseInlineContent
  -> InlineContent[]
  -> fitInlineContent
  -> PositionedInlineRun[]
  -> render.ts
  -> Canvas text / image
```

- `[icon:name]` をプロジェクト内の不変なasset IDへ解決する
- 未解決トークンは通常テキストとして残し、領域インスペクターに未登録名を列挙する
- アイコン高はフォントサイズ×`scale`、幅は元画像のアスペクト比で決める
- `ImageAsset`の`scale`、`baselineOffset`、`inlinePadding`（左右それぞれのem値）は全出現箇所の既定値としてアセット編集画面から調整できる
- `TextRegion.inlineAssetStyles`は`start`、`end`、不変な`assetId`と任意の表示設定を持ち、文字タブから訳文中の1出現箇所だけ既定値を上書きできる
- 訳文編集・CSV反映後は、同じアセット名の出現順を基準に個別設定の文字範囲を再計算する。トークン削除時は設定を破棄し、アセット名変更時はIDを基準に設定を維持する
- 文字と画像の合計幅で折り返し、縦に収まらなければサイズを縮小する
- 保護領域と左・中央・右揃えをインラインrunでも維持する
- TTF / OTF / WOFF / WOFF2はArrayBufferからFontFace APIへ登録する
- family名はID由来の内部名とし、表示名変更の影響を受けない
- 未ロードフォントは標準sans-serifへフォールバックし、UIで再選択を促す
- PNG/JPEGにはラスタライズされた画素だけが入り、フォントファイルは含まれない

## 現在の既知の課題

### 37枚プロジェクトでの実用確認（2026-09-09）

ChromeのOPFS上で37枚の読込、全カードを2周切替、保存・再読込、PNG/JPEG一括出力、5ページのA4 PDF生成を確認した。実フォルダの権限・ディスク速度と長時間操作は未確認。

訳文入力時にChromeから同じ値のtrusted inputイベントが5回届き、同一状態が複数回履歴へ追加される挙動を確認した。`useHistory`で同一状態のcommitを無視し、Redoを保持するよう修正済み。37枚の複製データで1回のUndo・Redoとカード切替後の独立した履歴を確認した。検証中の `ERR_UPLOAD_FILE_CHANGED` と一括処理後のカード復帰待機は、実フォルダで切り分ける。

和訳支援は、領域の役割・配置雛形、アイコンを含む原文整備、用語集再利用、AI翻訳候補の順に進める。役割は任意の自由入力として実装済みで、プロジェクト内の役割名の再利用と一覧の絞り込みができる。カード名・種別・効果などの固定構造をアプリの前提にしない。実カードを使った詳細な検証記録は公開資料に含めていません。

### 配置雛形（2026-09-09）

既存領域の2分割を追加。上下・左右、分割位置、分割後の原文と訳文を確認して適用する。保護領域は矩形交差で切り分け、手動マスクは局所座標を変換する。最初のIDを保持し、2つ目に新しいIDを付ける。分割全体が1履歴操作で、確認中に対象が変わった場合は適用を中止する。

プロジェクト保存済みの場合、領域一覧から任意の領域を配置雛形へ登録できる。`layoutTemplates` は任意フィールドで既存version 2ファイルを引き続き読み込める。雛形の位置・文字設定・保護領域・手動マスクを画像寸法比で変換し、重ね合わせ画面で選択・移動・倍率調整後に既存領域へ追加する。原文・訳文・部分文字スタイルは複製しない。追加はカード単位の1回の履歴操作で、雛形の登録はプロジェクト共通設定として未保存判定の対象になる。カスタムフォントの使用数と参照削除には雛形も含める。

### OCR

`TesseractOCRProvider`を実装済みです。選択領域を元画像から3倍へ拡大し、グレースケールとコントラスト補正を適用してから英語OCRへ渡します。保護領域は白く除外します。

- OCR結果は候補欄へ表示し、自動では元テキストを上書きしない
- 複数行と1行のページ分割モードを選択できる
- 複数行モードはTesseractの行座標から上→下、同一行では左→右に読み順を補正する
- Workerは初回認識時に作成し、以降の領域で再利用する
- Tesseract Worker、WASM core、英語学習データはNuxtからローカル配信する
- カード画像や切り出した領域を外部へ送信しない
- 別のOCRエンジンは`OCRProvider`を実装すれば差し替えられる
- 「領域を自動検出（試験）」は全体画像をsparse-textモードで認識し、近接行を候補へまとめる
- 候補はプロジェクトへ保存せず、確定時に選択候補だけを1回の履歴操作で領域化する

- 自動補修は複雑な模様、枠線、装飾を完全には再構成できない
- 黒文字の影や低コントラスト文字は検出強度の調整が必要な場合がある
- 検出強度を上げすぎると背景模様も文字と判定する可能性がある
- 4辺補間のため、大きな矩形では縦横の筋やぼけが見える場合がある
- 自動マスクの補修範囲プレビューを実装済み
- 手動マスクの追加・消しゴムブラシと1ストローク単位Undo／Redoを実装済み
- 保護領域は矩形のみで、回転したアイコンや複雑な輪郭には未対応
- 保護領域が多い場合のテキスト配置は行単位の簡易レイアウトであり、禁則処理には未対応
- 既存プロジェクトのカード一覧・切り替え・複数画像追加・フォルダ直下の画像一括追加・カード名変更・並べ替え・カード削除を実装済み
- 一括画像書き出しは既存の遅延ロード経路でカードを順次切り替え、各CanvasをPNG / JPEG化して一覧順の連番名で保存する
- カード切り替え時にUndo / Redo履歴をカードID別に退避し、同じカードへ戻ったときに復元する。履歴は現在セッションだけで、保存データには含めない
- フォルダアクセス権限はセッションをまたいで記憶していない
- カード編集とアセット編集は同じ親状態を保ったまま `v-show` で切り替え、Canvasを破棄しない
- カード画像とアセット切り出し元画像は、別のHTMLImageElement・Object URL・表示倍率として管理する
- アセット編集へ初めて切り替えた時は元画像未選択とし、画面固有の「画像を開く」で読み込む
- アセット元画像全体は保存せず、切り出した `assets/<asset-id>.png` だけをプロジェクトへ保存する
- 単なる画面切替では両画像を保持し、新しいカードまたは別プロジェクトを開いた時にアセット元画像を解放する
- アセット登録と背景透明化は矩形切り出しを基準とし、自由形状の輪郭切り抜きは未実装
- アセット背景透明化は外周連結色方式を基本とし、背景色の直接指定とプレビュー上からの採色にも対応する
- 透明化のON/OFF、背景色、許容色差、境界ぼかし、手動マスクは作成ドラフトだけに保持し、確定時に透過済みPNGへ焼き込む
- 確定後のアセットは名前、表示倍率、上下位置、左右余白を変更でき、元画像を再選択すればIDと表示設定を維持したまま再切り出しできる
- アセット編集操作はカード編集のUndo / Redo履歴へ含めない
- フォントのウェイト選択、部分フォント、ルビは未実装
- Translation Endpointはα機能としてHTTPクライアントと単体テストを実装済み。ローカル翻訳モックとのブラウザ結合動作を確認済みで、Cloudflare Pages版では無効
- OCRはTesseract.jsによる英語認識を実装済みで、他Providerへの差し替えに対応
